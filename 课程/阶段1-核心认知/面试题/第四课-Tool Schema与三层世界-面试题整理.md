# 第四课面试题整理

## 题目 1

**问题：** 为什么在学习 Agent 开发初期，不建议一开始就直接使用 LangChain 这类框架？

**参考答案：** 因为框架会把 Tool Schema 生成、Tool Call 解析、循环调度、上下文拼接等关键细节封装起来。虽然可以更快跑通 Demo，但学习者往往看不清 Agent 的底层工作原理，容易把 Tool Calling、Loop、结果回传等机制理解成“黑盒魔法”。在入门阶段先直接使用官方 SDK 和少量基础库，更有利于建立对 Agent 系统的真实认知。

**追问方向：** 在什么阶段开始引入 LangChain 才更合适？

**易错点：** 把“不用框架”理解成“框架没用”，而不是“先学底层再学封装”。

## 题目 2

**问题：** 为什么说一个 Tool 不只是一个 Python 函数？

**参考答案：** 因为 Python 函数只是工具的执行逻辑，而 LLM 并不直接理解函数体。要让模型能够正确选择并调用这个工具，还必须提供它的名称、描述、参数定义等元信息，也就是 Tool Schema。没有这层描述，模型无法稳定判断这个工具适合解决什么问题、需要什么输入、会返回什么结果。

**追问方向：** 如果只给函数不给 Schema，会发生什么？

**易错点：** 认为“函数能跑”就等于“模型会用”。

## 题目 3

**问题：** Tool Schema 本质上是什么？

**参考答案：** Tool Schema 本质上是一份提供给模型的接口文档，描述了工具的名称、用途、参数结构和约束。它的作用类似“API 文档 + 参数说明”，帮助模型理解什么时候应该调用这个工具，以及调用时应该构造什么样的参数。无论是 OpenAI、Claude、Gemini 还是 MCP，本质上都依赖某种形式的 Schema 来完成工具调用。

**追问方向：** Schema 中最容易被新人低估的是哪一部分，为什么？

**易错点：** 把 Schema 只理解成“参数列表”，忽略它对模型决策的引导作用。

## 题目 4

**问题：** 为什么 Description 往往比函数实现本身更影响 Tool Calling 效果？

**参考答案：** 因为模型在选择工具时，并不会先阅读和理解函数源码，而是优先依赖名称、描述和参数定义来判断这个工具是否适合当前任务。Description 越清晰，模型越容易把用户意图映射到正确工具；如果 Description 模糊，即使函数实现再完整，模型也可能不会调用或误调用。因此 Description 是 Tool 可用性的核心组成部分。

**追问方向：** 一个好的 Description 应该至少覆盖哪些信息？

**易错点：** 只关注代码实现正确性，忽略模型是否真的“懂这个工具”。

## 题目 5

**问题：** Agent 开发中为什么要区分“用户世界”“LLM 世界”“Python 世界”？

**参考答案：** 因为这三个层面的职责完全不同。用户世界处理自然语言需求，LLM 世界负责理解需求并生成结构化决策，例如 Tool Call，Python 世界负责真正执行函数、访问文件、联网或运行代码。很多初学者把这三层混为一谈，导致无法正确理解为什么模型不能直接执行函数、为什么需要 Schema、为什么工具结果还要回传给模型。因此区分这三个世界，是建立 Agent 系统思维的关键。

**追问方向：** 哪些常见误解，本质上都是因为把这三个世界混在一起了？

**易错点：** 认为模型“会写出函数名”就等于“它已经执行了函数”。

## 题目 6

**问题：** 为什么第四课虽然还没写完整业务代码，却依然很重要？

**参考答案：** 因为它完成了 Agent 开发中最关键的准备工作，包括最小依赖选择、项目结构搭建、配置隔离、Tool 与 Schema 的概念建立，以及三层世界模型的认知区分。这些内容决定了后续代码是否会走向清晰、可维护、可扩展的方向。没有这一步，后面的实现很容易沦为“能跑但不理解”的黑盒拼装。

**追问方向：** 如果跳过这一步，直接抄一份能跑的 Agent 示例，后面最容易在哪些地方卡住？

**易错点：** 低估环境、结构和认知分层的重要性，把它们当成纯准备动作。
