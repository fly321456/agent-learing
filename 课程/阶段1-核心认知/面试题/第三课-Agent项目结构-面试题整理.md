# 第三课面试题整理

## 题目 1

**问题：** 一个最小可用的 Agent，通常应该包含哪些核心模块？

**参考答案：** 一个最小可用的 Agent，通常至少包含 Prompt、Tools、LLM、Agent Loop，以及可选的 Memory。Prompt 负责定义角色和行为约束，Tools 提供外部执行能力，LLM 负责推理与决策，Agent Loop 负责接收模型输出、判断是否需要调用工具、执行工具并把结果回传给模型，Memory 则用于保存上下文与长期信息。不同框架封装方式不同，但本质模块大体一致。

**追问方向：** 这些模块中，哪个最容易在早期项目里被错误耦合到一起？

**易错点：** 只回答“模型和工具”，忽略了 Loop 和 Prompt 的系统地位。

## 题目 2

**问题：** 为什么第一个 Agent 项目也建议从一开始就拆成 `main.py`、`agent.py`、`tools.py`、`prompts.py`、`config.py`？

**参考答案：** 因为 Agent 项目天然会扩展，工具数量、Prompt 长度、控制逻辑和配置项都会持续增长。如果一开始全部堆在一个文件里，后续很快会失控。按职责拆分文件，可以让入口、配置、工具实现、Prompt 定义和循环控制分别独立，便于维护、调试和扩展。这不是形式主义，而是为了避免未来把简单 Demo 演变成无法维护的大脚本。

**追问方向：** 如果后续 Tool 数量从 3 个增长到 30 个，目录还应如何继续演进？

**易错点：** 把目录拆分理解成“只是代码风格问题”，没有看到它和扩展性的关系。

## 题目 3

**问题：** 为什么说 `agent.py` 才是 Agent 系统的核心？

**参考答案：** 因为 `agent.py` 通常承载的是 Agent Loop，它负责向 LLM 发起请求、解析返回结果、判断是否产生 Tool Call、执行工具、把工具结果重新喂回模型，并在循环中持续推进任务，直到最终完成。Tool 只是执行能力，Prompt 只是行为约束，而 Loop 才是真正让整个系统从“会说话”变成“会做事”的控制核心。

**追问方向：** 如果只有 Tool 没有 Loop，这个系统会退化成什么？

**易错点：** 认为 `tools.py` 才是最核心的，因为它“干活最多”。

## 题目 4

**问题：** 为什么 Agent 开发里反复强调“让 LLM 决策”，而不是在 Python 里写一堆 `if...else`？

**参考答案：** 因为大量 `if...else` 的本质是开发者手写分支，这属于 Workflow 思维，而不是 Agent 思维。Agent 的关键在于把“下一步做什么”交给模型根据上下文动态判断。开发者应该提供目标、工具和约束，而不是把所有路径提前写死。否则系统虽然表面上用了大模型，但本质上仍是传统规则驱动程序，无法体现 Agent 的动态规划能力。

**追问方向：** 什么情况下仍然应该保留少量显式规则，而不是完全依赖模型？

**易错点：** 把“让 LLM 决策”理解成完全不要程序控制，忽略了调度、权限和安全边界仍然需要代码负责。

## 题目 5

**问题：** 什么叫“薄 Controller”，为什么现代 Agent 项目喜欢这个原则？

**参考答案：** 薄 Controller 指的是宿主程序尽量只负责调度，不负责写死业务决策。也就是只做这些事情：把 Tool 定义交给模型、接收模型输出、执行 Tool Call、回传 Tool Result、终止循环。它不应该充满“如果问天气就调天气、如果问股票就调股票”这类显式业务分支。这样做的好处是职责清晰、扩展简单，并且真正把决策权交给模型，而不是把模型降级成普通流程中的一个组件。

**追问方向：** 薄 Controller 和“完全无控制”有什么区别？

**易错点：** 把薄 Controller 误解成“程序什么都不用做”。

## 题目 6

**问题：** 第一个 Agent 只做 Calculator、Read File、Current Time 三个 Tool，有什么意义？

**参考答案：** 这种设计的意义在于用最小复杂度覆盖 Agent 最核心的三类能力验证：计算能力、文件访问能力和环境查询能力。它既足够简单，方便理解 Tool Calling 和 Loop；又足够真实，能体现“模型决策 + 外部执行 + 结果回传”的完整闭环。也就是说，这不是功能随便选，而是在用最低成本验证 Agent 架构是否成立。

**追问方向：** 如果要在这个基础上扩展第四个 Tool，你会优先加什么，为什么？

**易错点：** 只把它当成教学示例，没有理解这是“最小可运行闭环”的刻意设计。
