# 第12课面试题整理

## 题目 1

**问题：** 为什么实现第一个最小 Agent 时，应该先写 Tool，而不是先写 `class Agent`？

**参考答案：** 因为 Agent 的执行能力本质上来自 Tool，没有 Tool，Agent 只是一个没有外部行动能力的空壳。先写 Tool，可以先明确系统到底具备哪些可执行动作，再围绕这些动作设计 Schema、模型调用和 Loop。这样开发顺序更符合 Agent 的本质，也能避免一开始就把大量职责堆进 Agent 类里。

**追问方向：** 如果先写 Agent 类再回头补 Tool，最容易出现什么设计问题？

**易错点：** 把 Agent 理解成一切能力的中心，而忽略能力来源其实是 Tool。

## 题目 2

**问题：** 为什么 `time_schema` 这种 Schema 不是“多余配置”，而是 Agent 必需的一部分？

**参考答案：** 因为 LLM 并不认识 Python 函数本身，它只能根据结构化工具描述来判断是否应该调用某个 Tool。Schema 提供了工具名称、用途、参数结构等信息，相当于给模型的说明书。没有这层结构化描述，模型就无法稳定地知道工具存在、适用于什么问题以及该如何构造参数，因此 Schema 是 Tool Calling 的关键组成部分，而不是可选装饰。

**追问方向：** 如果一个 Tool 没有 Schema，但 Python 端函数写得很好，会发生什么？

**易错点：** 认为函数实现正确就足够，不需要额外描述层。

## 题目 3

**问题：** 为什么说一个最小 Agent 的核心其实就是 `while True`？

**参考答案：** 因为 Agent 不是一次模型调用后就结束，而是要不断重复“调用模型 - 判断是否有 Tool Call - 执行 Tool - 回传结果 - 再次调用模型”这个过程，直到任务真正完成。这个持续迭代的控制结构天然对应一个循环，而 `while True` 正是最直接的表达方式。很多复杂框架的本质，也只是把这个循环工程化和抽象化。

**追问方向：** 在什么情况下，这个 `while True` 会演变成更明确的状态机或图结构？

**易错点：** 把 Agent 简化成“模型调用 + 一个函数执行”。

## 题目 4

**问题：** 为什么 Claude Code 这类 Coding Agent 天生离不开 Loop？

**参考答案：** 因为真实编码任务几乎不可能通过一次模型调用就结束。它通常需要先读文件、再搜索错误、再修改代码、再运行测试、根据失败结果继续修复，形成多轮观察、决策和行动的过程。每一步新的工具结果都会改变下一步决策，因此这类系统天然需要 `LLM -> Tool -> LLM -> Tool -> ...` 的循环结构，而不是单次请求响应模式。

**追问方向：** Loop 增多之后，系统最先需要补强的是哪些工程能力？

**易错点：** 觉得 Loop 只是实现习惯，而不是任务本质要求。

## 题目 5

**问题：** 为什么在入门阶段先自己实现最小 Agent，比直接使用 OpenAI Agents SDK 更有价值？

**参考答案：** 因为自己实现最小 Agent 能直接暴露 Agent 的核心机制，包括 Tool Schema、模型决策、工具执行、结果回传和 Loop 控制。这样以后再看官方 SDK 时，就能把 `Runner.run()`、Tool 包装、Session 管理等抽象还原回自己亲手写过的基础逻辑。反过来，如果一开始就只会用框架 API，很容易停留在“会调用，但不会实现”的层面。

**追问方向：** 自己实现过最小 Agent 后，再去读官方源码，理解上会有哪些变化？

**易错点：** 把“自己手写”理解成重复造轮子，而没有看到它的学习价值。

## 题目 6

**问题：** 为什么说“框架不是魔法，它只是把你会写的代码封装起来”？

**参考答案：** 因为像 OpenAI Agents SDK 这类框架，对外提供的 `Runner.run()`、Tool 封装、Tracing、Retry、Memory 等能力，本质上都建立在开发者自己也能写出来的基础逻辑之上，比如 `while True` 循环、响应解析、工具分发和结果回传。框架做的是把这些重复模式抽象、标准化并增强为可复用运行时，而不是引入完全不同的新原理。理解这一点，才能真正从框架使用者成长为框架理解者和设计者。

**追问方向：** 一个优秀框架通常会在“自己能写的最小逻辑”之上，额外补哪些工程能力？

**易错点：** 把框架视为黑盒能力来源，而不是工程化封装。
