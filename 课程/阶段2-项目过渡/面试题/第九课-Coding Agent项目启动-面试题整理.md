# 第九课面试题整理

## 题目 1

**问题：** 为什么在 Agent 项目进入真实开发后，不能继续把所有逻辑都写在 `main.py` 里？

**参考答案：** 因为随着能力扩展，Agent 系统很快就会包含模型调用、Tool 管理、Session、Memory、Prompt、MCP、测试和运行时控制等多个部分。如果所有逻辑都堆在 `main.py`，很快会形成高耦合的大脚本，既难维护也难扩展，更无法演进成框架。真正的 Agent 工程需要从一开始就按职责拆分模块，把配置、运行时、工具、记忆和会话分别组织起来。

**追问方向：** 一个从 Demo 演进到框架的项目，通常最先需要拆分的是哪几层？

**易错点：** 觉得“先写在 main.py 后面再重构”总是没问题，忽略了早期结构选择对后续演进的影响。

## 题目 2

**问题：** 为什么第一版只实现 `Agent` 类，而不是一口气把整个系统都写完？

**参考答案：** 因为框架设计的第一原则不是“功能堆得快”，而是“职责划分清楚”。如果一开始就把运行、工具调用、记忆、重试、持久化等逻辑都塞进一个类，很容易得到一个不可维护的上帝对象。先单独实现 `Agent`，可以先明确它的职责边界，即只负责描述智能体的身份、模型、指令和工具集合，为后续 Runner、Session、Memory 等模块留出清晰的接口空间。

**追问方向：** 在什么信号出现时，说明某个类已经开始承担过多职责？

**易错点：** 把“先少写一点”误解成只是教学节奏慢，而不是工程策略。

## 题目 3

**问题：** `Agent` 和 `Runner` 的职责边界应该如何划分？

**参考答案：** `Agent` 更适合承载静态配置，例如名称、Instructions、模型、工具集合和行为边界；`Runner` 则负责动态运行时逻辑，例如接收输入、调用模型、解析响应、执行 Tool、维持 Loop、处理生命周期与状态流转。简化来说，Agent 负责“我是谁”，Runner 负责“我怎么运行”。这种划分符合单一职责原则，也让系统更容易支持多个 Agent 和更复杂的运行时编排。

**追问方向：** 如果未来要支持 Multi-Agent，这种拆分会带来什么好处？

**易错点：** 认为 `agent.run()` 和 `Runner.run(agent)` 只是写法差异，而不是架构差异。

## 题目 4

**问题：** 为什么说 Agent 更像 Configuration，而 Runner 更像 Runtime？

**参考答案：** 因为 Agent 主要保存的是静态定义，例如名字、Prompt、模型和 Tools，这些信息共同描述了一个智能体“是什么”；而 Runner 负责实际运行过程，包括进入 Loop、处理响应事件、调度 Tool、维护状态和控制生命周期，它描述的是系统“怎么工作”。前者偏配置，后者偏执行。把这两层分开，是现代 Agent Framework 非常核心的设计模式。

**追问方向：** 如果把 Runtime 逻辑塞回 Agent，会在长期演进中造成什么问题？

**易错点：** 只从代码组织看待 Configuration/Runtime，而没有看到这是运行时抽象。

## 题目 5

**问题：** 一个“GitHub 项目分析 Agent”的 Agent 层应该保存哪些配置？Runner 层应该负责哪些事情？

**参考答案：** Agent 层通常应保存名称、角色说明、分析目标、所用模型、可用工具集合以及必要的行为约束；Runner 层则负责接收用户请求、发起模型调用、处理 `response.output`、执行工具、维护循环、管理 Session、协调 Memory 并产出最终结果。前者定义能力，后者驱动生命周期。这个拆分能让系统既易于复用，也方便扩展到多任务、多 Agent 或不同运行策略。

**追问方向：** 如果要求加入“失败重试”和“超时中断”，更应该放在哪一层？

**易错点：** 把所有“和 Agent 有关的东西”都归到 Agent 类里。

## 题目 6

**问题：** 为什么说这一课标志着课程从“学习 Agent”转向“设计 Agent Framework”？

**参考答案：** 因为课程重点已经从理解概念和调用 API，转向建立模块边界、区分配置与运行时、规划项目结构，并围绕一个真实 Coding Agent 项目进行持续演进。这种训练方式不再只关心“能不能调通模型”，而是关心系统能否扩展到 Tool、Memory、Session、MCP、Tracing 和多 Agent 等能力。这正是从使用者视角迈向框架设计者视角的关键转折点。

**追问方向：** 一个系统从“会用”升级到“会设计”，思维上最大的变化是什么？

**易错点：** 把这一课看成只是换了一个项目目录，没有意识到设计目标已经变化。
