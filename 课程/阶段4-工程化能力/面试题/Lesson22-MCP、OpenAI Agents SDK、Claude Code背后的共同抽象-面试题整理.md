# Lesson22：MCP、OpenAI Agents SDK、Claude Code 背后的共同抽象 - 面试题整理

## 1. 为什么学习 Agent 框架不能只停留在 API 层？

### 参考答案

因为如果只学 API，用的始终是“表层记忆”：

- 这个类怎么实例化
- 那个方法怎么调用
- 这个字段怎么传

一旦框架更换，之前的经验就很容易失效。

而如果你理解了框架背后的共同抽象，就能跨系统迁移理解，例如识别：

- 能力层
- 状态层
- 调度层
- 信息层
- 治理层

所以真正稳定的学习对象不是具体 API，而是底层结构。

---

## 2. 为什么说成熟 Agent 系统最终都会围绕“能力、状态、调度、信息、治理”收敛？

### 参考答案

因为无论表面形态如何，成熟 Agent 系统都必须回答几类共同问题：

1. 系统能做什么
2. 当前处于什么状态
3. 下一步怎么推进
4. 当前决策需要哪些信息
5. 系统如何被控制、观察和评估

这些问题具有普遍性，所以抽象结构会自然收敛。

因此不同框架虽然长相不同，但底层会不断出现相似骨架。

---

## 3. 什么是 Agent 系统里的“能力抽象”？

### 参考答案

能力抽象回答的是：

> **系统到底能做什么。**

它在不同系统里可能表现为：

- Tool
- function tool
- 文件能力
- 搜索能力
- 外部 MCP 能力

虽然名字不同，但本质上都在声明：

> **哪些能力可以被 Agent Runtime 调用。**

---

## 4. 什么是 Agent 系统里的“状态抽象”？

### 参考答案

状态抽象回答的是：

> **系统当前处于什么位置，已经做了什么，还剩什么没做。**

它通常会体现为：

- Session
- context
- summary
- completed / pending
- task state
- checkpoint state

因为 Agent 是运行过程，而不是一次函数调用，所以成熟系统一定会长出状态抽象。

---

## 5. 什么是 Agent 系统里的“调度抽象”？

### 参考答案

调度抽象回答的是：

> **下一步该做什么，什么时候继续，什么时候暂停，什么时候结束。**

它可能表现为：

- `while True` 循环
- Runner
- lifecycle orchestration
- pause / resume
- waiting_for_human

所以调度抽象的本质，是控制能力和状态如何在时间上推进。

---

## 6. 什么是 Agent 系统里的“信息抽象”？

### 参考答案

信息抽象回答的是：

> **当前决策需要哪些信息，这些信息来自哪里，如何被组织进上下文。**

典型来源包括：

- current messages
- summary
- Memory
- RAG
- Tool result

所以信息抽象关注的不只是“有信息”，而是“如何组织多来源信息进入模型上下文”。

---

## 7. 什么是 Agent 系统里的“治理抽象”？

### 参考答案

治理抽象回答的是：

> **系统如何被控制、观察、恢复、评估和审计。**

它通常表现为：

- tracing
- eval
- retry / timeout
- checkpoint
- human handoff
- 权限控制

随着 Agent 从 Demo 走向真实系统，这层能力一定会变得越来越重要。

---

## 8. 为什么说 MCP、OpenAI Agents SDK、Claude Code 虽然不同，但共享相似系统骨架？

### 参考答案

因为它们虽然重点不同，但都在围绕类似根问题建模：

- 有哪些能力
- 如何组织状态
- 如何推进运行
- 如何组织信息
- 如何治理系统

MCP 更偏能力互操作层，Agents SDK 更偏单 Agent 运行时抽象，Claude Code 更偏复杂任务下的调度与治理整合。

但它们共享相似的骨架结构。

---

## 9. MCP、OpenAI Agents SDK、Claude Code 三者分别更偏重哪些抽象层？

### 参考答案

可以这样粗略理解：

### MCP

更偏：

- 能力层
- 互操作层

### OpenAI Agents SDK

更偏：

- 单 Agent 运行时
- 调度层
- Tool 使用组织

### Claude Code

更偏：

- 长链路调度
- 状态治理
- 复杂任务执行与可观测性

所以它们并不是互相替代，而是在不同层面解决 Agent 系统问题。

---

## 10. 为什么说“看懂共同抽象”是从会用框架到能设计框架的关键一步？

### 参考答案

因为会用框架通常意味着：

- 知道怎么调 API
- 知道怎么跑 Demo

而能设计框架意味着：

- 能识别核心问题属于哪一层
- 能判断缺的是能力、状态、调度、信息还是治理
- 能自己做模块边界决策

这要求你看到具体实现背后的稳定结构，而不是只盯着代码表面。

所以共同抽象识别能力，是工程设计能力的重要基础。

---

## 11. 为什么说这一步本质上是在训练“从具体实现中抽离稳定结构”的能力？

### 参考答案

因为框架表面代码永远会变：

- 类名会变
- API 会变
- 组织方式会变

但底层反复出现的核心问题不会变：

- 能力怎么暴露
- 状态怎么维护
- 调度怎么推进
- 信息怎么组织
- 系统怎么治理

所以学习共同抽象，实际上是在训练你从细节中识别稳定结构的能力。

这是一种非常核心的高级工程能力。

---

## 12. 如果让你用五层抽象重新描述自己的 Agent 项目，你会怎么做？

### 参考答案

我会这样拆：

### 能力层

Tool / MCP 能力 / 外部可调用能力

### 状态层

Session / summary / completed / pending / checkpoint

### 调度层

Runner / run loop / pause-resume / human handoff

### 信息层

recent context / Memory / RAG / injected knowledge

### 治理层

tracing / eval / retry / timeout / audit

这种描述方式比只列文件名更接近系统本质。

---

## 13. 面试时如何简洁总结这一课？

### 参考答案

可以这样回答：

> 虽然 MCP、OpenAI Agents SDK、Claude Code 表面上长得不一样，但成熟 Agent 系统最终都会围绕能力、状态、调度、信息、治理这几个共同抽象收敛。理解这些共同抽象，比记住某个框架的具体 API 更重要，因为这决定了你是否具备跨系统迁移理解和自主做架构设计的能力。
