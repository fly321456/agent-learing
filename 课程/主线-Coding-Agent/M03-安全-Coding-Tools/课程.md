# M03 安全 Coding Tools

## 里程碑目标

让 Agent 能在限定工作区读取、搜索、修改和验证代码，同时把越界路径、写操作和命令执行的风险变成明确的 Runtime 约束。

## 必须交付

- `read_file`：严格读取工作区内 UTF-8 文本。
- `search_files`：限制目录、结果数量并跳过二进制内容。
- `apply_patch`：使用精确替换，歧义修改必须失败。
- `run_command`：只接收 argv 数组，不经 shell，支持 cwd 与超时。
- 所有工具返回 `ToolResult`，写入和执行默认需要审批。
- 路径解析后必须仍位于统一工作区。

## 代码入口

- `src/agent_from_scratch/tools.py`
- `src/agent_from_scratch/errors.py`
- `tests/test_tools.py`
- `tests/test_e2e_coding_tools.py`

## 安全模型

安全不是在 Prompt 中写“请小心”，而是由代码执行边界保证：

1. 所有相对路径基于 `ToolContext.workspace` 解析。
2. 解析后的真实路径必须能 `relative_to(workspace)`。
3. `write` 和 `execute` 风险级别必须经过审批回调。
4. 命令不启用 shell，避免字符串解释和拼接注入。
5. 超时、拒绝、异常是不同状态，不能都压成失败字符串。

## 实作任务

1. 在临时目录完成读取、搜索、补丁、运行检查的闭环。
2. 尝试读取 `../outside.txt`，确认返回边界错误。
3. 不提供审批回调执行补丁，确认文件保持不变。
4. 运行一个睡眠命令，确认超时被结构化记录。
5. 解释符号链接、Windows 盘符和大小写可能带来的路径风险。

## 自动验证

```powershell
cd agent-from-scratch
python -m pytest -q tests/test_tools.py tests/test_e2e_coding_tools.py
```

## 常见失败

- 只检查路径字符串是否以工作区开头，产生前缀绕过。
- 将整条命令作为字符串交给 shell。
- 审批发生在工具执行之后。
- 补丁找不到目标时仍返回成功。
- 把 stderr 非空等同于命令失败，或忽略 exit code。

## 完成定义

Agent 可在临时仓库完成小型修复；越界、拒绝和超时均不会产生未授权副作用；结果可被 Runner 和测试稳定消费。
