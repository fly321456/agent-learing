# 模块 01 练习参考答案

## L01 从一次回答到行动轨迹

### 基础实验一：让结论使用真实 README

思路是先把 README 内容保存为 Observation，再从这条 Observation 生成 Finish。只改最后一句固定文本，不算完成，因为环境变化仍无法传到答案。

```python
def run_small_agent(task: str) -> list[str]:
    del task
    files = sorted(REPOSITORY)
    readme = REPOSITORY["README.md"]
    return [
        "Decision: inspect the file list",
        f"Observation: files = {files}",
        "Decision: read README.md",
        f"Observation: {readme}",
        f"Finish: repository description = {readme}",
    ]
```

测试时把 README 从 calculator 改成 todo，确认 Observation 和 Finish 同时变化。常见错误是直接在 Finish 再读一次全局字典，这会让结果正确，却没有展示“观察驱动答案”的数据流。

### 基础实验二：观察 Python 配置

先在环境加入 `pyproject.toml`，再根据文件列表产生一条独立 Observation。不要让 `list_files` 同时负责总结；工具只提供事实，解释由决策阶段完成。

### 进阶挑战：`choose_next_action`

可以用观察数量和状态做最小决策：空历史时列文件；看到 README 名称时读取；读取成功后完成；缺失时查看 Python 文件。此处不必追求通用协议，重点是验证不同 Observation 会返回不同 Action。

## L02 四要素故障与扩展

### 新增 Python 文件计数工具

```python
def count_python_files() -> int:
    return sum(name.endswith(".py") for name in REPOSITORY)

TOOLS["count_python_files"] = count_python_files
```

在预设决定中把计数调用放在 Finish 前。运行后观察数量应依次为 0、1、2、3。若每次都是 0，说明 Observation 列表被错误地创建在循环内部。

### 让失败观察改变决定

关键不是用 `round` 猜当前状态，而是检查最新观察：

```python
def decide(self, task, observations):
    del task
    if not observations:
        return {"type": "tool", "name": "read_file", "arguments": {"path": "README.md"}}
    latest = observations[-1]
    if latest["status"] == "missing":
        return {"type": "tool", "name": "list_files", "arguments": {}}
    return {"type": "finish", "answer": str(latest["output"])}
```

常见错误是 Tool 捕获异常后返回空字符串，使决策器无法区分空文件与缺失文件。更好的做法是由 Loop 形成明确 `status`。

## L03 Workflow 与 Agent 选型

### 为 Workflow 增加稳定分支

```python
def safer_workflow(repository: dict[str, str]) -> str:
    if "README.md" in repository:
        return repository["README.md"]
    return f"No README. Files: {', '.join(sorted(repository))}"
```

当场景只有“存在或缺失”两个稳定分支时，这个 Workflow 通常优于 Agent：执行路径确定、无需模型调用、测试简单。Agent 的价值应来自大量不可提前穷举的语义路径，而不是为了消灭一个 `if`。

### JavaScript 仓库与维护成本

Workflow 需要新增检查 `package.json` 的显式分支；Agent 决策器也需要知道它可以读取哪些文件，但可以依据文件内容继续选路。不要只比较代码行数，要比较输入变化速度、错误风险和审计要求。

### 混合方案

```python
def hybrid(repository: dict[str, str]) -> str:
    if "README.md" in repository:
        return workflow(repository)
    return agent(repository)
```

正常仓库走低成本确定路径，异常仓库才进入探索。测试应断言有 README 时没有 Agent Trace，没有 README 时至少产生一次 Observation。

## L04 完整闭环与失败语义

### 新增搜索工具

```python
def search_files(keyword: str) -> list[str]:
    return sorted(path for path in REPOSITORY if keyword.lower() in path.lower())

tools = {
    "read_file": read_file,
    "list_files": list_files,
    "search_files": search_files,
}
```

预设顺序可以是读取失败、列目录、搜索 `main`、Finish。检查 Trace 中三条工具记录的步骤号依次为 1、2、3。

### 超时后重试

使用有状态 Fake Tool：

```python
class FlakyTool:
    def __init__(self) -> None:
        self.calls = 0

    def __call__(self) -> str:
        self.calls += 1
        if self.calls == 1:
            raise TimeoutError("temporary timeout")
        return "recovered"
```

本模块由 `ScriptedLLM` 决定第二次调用同一工具。Loop 只负责把第一次失败反馈回去，不应在不了解副作用的情况下偷偷重试。模块 6 会系统学习 Retry 与幂等。

### 实时步骤回调

最小实现是在 `trace.append(entry)` 后调用 `on_step(entry.copy())`。需要覆盖 Finish、未知工具、成功和错误四个追加位置。常见错误是只在成功工具后触发，导致界面看不到失败和最终答案。
