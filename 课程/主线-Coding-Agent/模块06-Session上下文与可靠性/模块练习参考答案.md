# 模块 6 练习参考答案

## L21 Session、Turn 与 Run

两个 Turn 应共享 session_id，但各有独立 turn_id；每次 Runtime 执行有 run_id。恢复原 Run 时保留 run_id，不新增用户 Turn。按 turn_id 分组比按消息相邻位置更稳定，因为后续可能插入系统摘要。

持久化版本可在顶层增加 `schema_version`。读取未知更高版本时明确拒绝，避免旧代码静默丢新字段。

## L22 Context 预算

裁剪函数应返回派生列表，不修改 `session.messages`。按 Turn 裁剪时，从最新 Turn 向前累计整个 user/assistant 组；单 Turn 超预算应拒绝、分块或完整保留并报告超限，不能静默切半。

```python
result = ContextWindow(25).build(messages, summary="inspected config")
assert result.truncated
assert result.messages[-1].content == "latest"
assert len(session.messages) == 3
```

## L23 Checkpoint 与幂等

去重键应至少是 `(run_id, call_id)`。完整实现保存 ToolResult 而非 output 字符串，并区分 pending/completed/failed。外部 API 应使用同一幂等键；仅靠本地 JSON 无法消除“副作用成功但保存前崩溃”的窗口。

## L24 Retry 与 Config

`attempts=2` 表示最多调用两次。事件在第一次 Retryable 失败后产生；第二次仍失败则原异常上抛。DeterministicError 不进入 except，调用数保持 1。

可注入 `sleep_fn` 使测试断言退避序列而不真实等待。Run deadline 应在每次 attempt 前计算剩余时间，并把较小值传为单次 Timeout。

## 综合排障

“继续”失忆先检查 Session 是否加载；上下文过长先检查预算账本；恢复重复修改先检查 call_id 与 Checkpoint 保存时机；任务异常缓慢先检查 retry Event。不要用更长 Prompt 掩盖状态协议错误。
