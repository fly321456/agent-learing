# L20 审批、超时与危险操作：能力越强，停止边界越要明确

> 建议学习时间：60–90 分钟。本课完成模块 5 安全 Coding Tools 检查点。

## 1. 本节要解决的真实问题

路径限制只能保证操作发生在仓库内，不能保证操作值得执行。删除源码、覆盖配置或运行高耗时命令都可能合法地位于 Workspace。Coding Agent 还需要风险分级、人工审批和 Timeout；没有这些边界，Instructions 中“请小心”无法替代执行控制。

问题链是：哪些 Tool 默认审批？没有审批回调时放行还是拒绝？拒绝与执行失败有何不同？Timeout 是异常、错误还是独立状态？审批应该看到什么参数？一次批准能否永久复用？

## 2. 前置回顾：三层安全边界

```text
路径边界：能否触达这个位置？
审批边界：是否允许这次副作用？
时间边界：允许它运行多久？
```

三层互不替代。工作区内命令仍可能危险；审批过的命令仍可能卡死；超时终止也无法挽回已经发生的部分副作用。因此工具设计还应尽量幂等、最小化。

## 3. 风险模型与两个案例

教学版使用 `read / write / execute` 三档。read 默认无需人工确认；write 和 execute 每次调用都要求审批。

案例一：Agent 请求读取 `README.md`，路径合规即可执行。案例二：请求 `apply_patch`，Manager 把 Tool 名和 arguments 交给 approval callback；用户拒绝后返回 denied，handler 根本不运行。案例三：命令获批但 sleep 超过 0.3 秒，返回 timeout。

风险等级是最低策略，不代表所有读取永远安全。真实产品可把敏感文件读取也设为审批，但不要在本课提前构建复杂策略语言。

## 4. ToolContext 与审批回调

```python
@dataclass(frozen=True)
class ToolContext:
    workspace: Path
    approval: ApprovalCallback | None = None
    command_timeout: float = 30.0
```

Context 表示当前运行环境，不塞进 Agent 静态身份。回调接收 ToolSpec 与 arguments，界面才能展示“将运行哪个命令、在哪个目录”。若没有回调，副作用 Tool 默认 denied，这是 fail closed；默认放行会让忘记配置审批变成安全漏洞。

## 5. 本课唯一代码增量：执行前闸门

```python
if tool.requires_approval and (
    context.approval is None or not context.approval(tool, call.arguments)
):
    return ToolResult(
        call.id, call.name, "denied", error=f"Approval denied for {call.name}"
    )
```

审批必须发生在 handler 之前。先执行再询问只是通知，不是控制。每次调用独立审批，避免模型改变参数后沿用旧许可。

## 6. Timeout 与结构化状态

```python
except subprocess.TimeoutExpired:
    return ToolResult(
        call.id, call.name, "timeout",
        error=f"Tool {call.name} timed out after {context.command_timeout:g}s",
    )
```

timeout 与 error 分开，因为恢复动作不同：超时可改用更小测试或增加经过批准的预算；确定性语法错误重试通常无效。denied 更不是 error，它表达策略决定，Runner 应停止或请求用户调整，而不是偷偷重复。

## 7. 两个错误直觉与纠正

### 误区一：只拦截 rm、del 等危险关键字

危险可以通过 Python、脚本或构建工具间接发生，关键字黑名单很容易绕过。教学版对所有 execute 审批，以清晰边界替代脆弱猜测。

### 误区二：Timeout 后再重试几次总会成功

命令可能本来就超预算，盲目重试重复消耗，写命令还可能重复副作用。是否重试取决于错误分类和幂等性，不能由 ToolManager 自动决定。

另一个误区是用户批准 Tool 名就永久信任。审批对象应包含本次 arguments；`pytest` 与 `pytest; delete` 不能共享许可。

## 8. 完整拒绝与超时轨迹

```text
ToolCall d1: run_command(...)
  → risk=execute
  → approval returns false
  → ToolResult status=denied
  → subprocess never starts

ToolCall t1: run_command(python sleep)
  → approval returns true
  → subprocess starts with timeout=0.3
  → TimeoutExpired
  → ToolResult status=timeout
```

两种结果都保留 call_id，Event 可以准确显示哪个请求被拒绝或超时。

## 9. 模块最终安全闭环

```text
search/read (bounded observation)
  → exact patch proposal
  → approval
  → unique write inside workspace
  → approved argv command
  → structured exit/timeout result
  → final explanation with evidence
```

源码位于 [course_tools](../../../agent-from-scratch/course-checkpoints/05-coding-tools/src/course_tools/)，Demo 只在临时目录操作。这个检查点没有“万能 shell”，每项能力都有窄接口和可测试失败语义。

## 10. 运行、预期输出与故障实验

```text
approval=denied command=timeout
```

故障实验：移除 approval 回调确认仍拒绝；把审批放到 handler 后观察风险；让命令非零退出区分 error 与 timeout；把 timeout 设为 0 确认配置立即失败；记录审批时展示的完整 argv。
