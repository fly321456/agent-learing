# M08 扩展与作品化

## 里程碑目标

把项目整理成可克隆、可安装、可演示、可解释的 Coding Agent 作品，并通过最小 MCP 实验理解工具互操作；RAG、Web 和多 Agent 只在边界与评测成立时扩展。

## 必须交付

- `coding-agent` 是主线产品入口，支持工作区、步骤、Session、恢复和 Trace 参数。
- README 提供安装、离线演示、真实运行、安全边界和架构说明。
- `coding-agent-mcp` 暴露最小只读 MCP 工具，不污染 stdio。
- `examples/` 提供无需密钥的运行示例。
- 评测结果、已知限制和设计取舍可以用于作品答辩。
- 对多 Agent 先做可拆分性审计，不满足条件时明确不实现。

## 代码入口

- `src/agent_from_scratch/cli.py`
- `src/agent_from_scratch/mcp_server.py`
- `examples/offline_demo.py`
- `README.md`
- `evals/cases.json`

## CLI 是必修界面

CLI 能直接消费 `RunResult` 和 Event，依赖少、便于自动化，也能暴露真实 Runtime 设计。Web 工作台需要额外的流式传输、身份、存储和前端状态协议，因此保留为选修，不能用设计稿冒充已交付能力。

## MCP 最小实验

MCP 只证明现有 Tool 能通过标准协议暴露。第一版只提供读取与搜索，使用官方 Python SDK 1.x 的 `FastMCP`；stdio 服务不得向 stdout 写调试日志。

## 扩展门槛

- RAG：只有任务集证明外部知识缺失是主要失败源时引入。
- Web：只有 CLI 事件协议稳定，并明确用户工作流时引入。
- 多 Agent：只有任务可独立拆分、角色边界清晰、单 Agent 基线和局部评测存在时引入。

## 实作任务

1. 在新环境按 README 完成安装和离线演示。
2. 启动最小 MCP server，确认创建 `FastMCP` 实例。
3. 录制一次 CLI 工具过程，能够解释每个事件。
4. 对一个复杂任务填写多 Agent 可拆分性审计，允许结论是“不拆”。
5. 写出项目的三个已知限制和下一步实验假设。

## 常见失败

- README 仍指向根目录旧脚本。
- Web 只有课程文档，没有可运行代码，却被列为必修成果。
- MCP 重新实现一套 Tool 逻辑，产生两个事实来源。
- 为展示“高级”过早引入多 Agent，无法归因失败。
- 作品只展示成功 Demo，没有测试、限制和评测证据。

## 完成定义

陌生开发者能按 README 安装并运行离线示例；CLI、测试、评测和 MCP 入口均可验证；扩展内容有进入门槛，项目可在面试中完整答辩。
