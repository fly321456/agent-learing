# 模块 4 导学：Runtime 模块化重构

## 模块位置

模块 3 已经证明最小 Agent Loop 可以工作。现在重构不是为了展示设计模式，而是为了让不同生命周期的数据不再互相污染，并让模型、工具和执行循环能够分别测试。

```text
L13 Agent 配置：它是谁、拥有什么能力
  ↓
L14 LLMResponse：一次模型调用返回了什么
  ↓
L15 ToolResult：一次行动实际发生了什么
  ↓
L16 RunResult + Event：整次运行如何结束、如何追踪
```

## 学习目标

完成模块后，你应能解释三种 Result 为什么不能合并；能指出 Runner 读取供应商 `raw_response` 的依赖泄漏；能用 ScriptedLLM 离线验证两轮 Tool Loop；能根据生命周期判断字段属于 Agent、Runner 还是 Run。

## 学习方式

每课先运行 `steps/lXX_*.py`，再阅读 `src/course_runtime/` 对应文件。不要一开始照抄最终参考实现；先手工画出数据流，再比较模块 3 单文件与模块 4 包结构。

```powershell
cd agent-from-scratch/course-checkpoints/04-runtime-refactor
python steps/l13_agent_configuration.py
python steps/l14_llm_response.py
python steps/l15_tool_manager.py
python steps/l16_runner_results.py
python demo.py
```

## 模块边界

本模块不实现真实 OpenAI 调用、安全文件工具、审批、超时、Session 或 Retry。它们需要当前接口作为地基，但不应提前挤进同一课。最终公共接口参考 `agent-from-scratch/src/agent_from_scratch/`，本检查点只代表学到模块 4 时的能力。

## 学习产物

- 一份独立 `src/course_runtime/` 标准包快照。
- 四个逐课步骤脚本和一个两轮 Agent Demo。
- 能区分 `LLMResponse`、`ToolResult`、`RunResult` 的手绘轨迹。
- 一份对“为何不把 run 放进 Agent”的设计答辩。
