## L13 参考：字段归属

`name`、`instructions`、默认 `max_steps` 属于 Agent 配置；`retry_attempts` 和事件 sink 更适合作为 Runner 依赖；`run_id`、`current_step`、events 属于一次 Run。`workspace` 的归属取决于产品：若一个 Runner 固定服务单仓库，可作为运行环境；若每个任务选择仓库，应显式作为 run context。判断依据不是字段名字，而是生命周期、复用范围和并发隔离。

```python
reviewer = Agent("reviewer", "Read only; report risks.", llm, read_tools)
fixer = Agent("fixer", "Inspect, patch, then test.", llm, coding_tools)
```

常见错误是把 `events=[]` 设为共享默认值，或把历史写进可复用 Agent。测试方式：连续运行两次，断言 run_id 不同且事件列表不是同一对象。

## L14 参考：两轮 ScriptedLLM

```python
llm = ScriptedLLM([
    LLMResponse(tool_calls=[ToolCall("c1", "echo", {"text": "hi"})]),
    LLMResponse(content="done"),
])
```

第一次响应描述模型请求，第二次响应描述模型总结。两者都不是整次 RunResult。若增加 usage，它应属于单次 LLMResponse，因为每次 API 调用都有独立 token 统计；Run 级总量可由 Runner 聚合，但不应覆盖单轮事实。

## L15 参考：uppercase 与失败

```python
tool = ToolSpec(
    "uppercase",
    "Return text converted to uppercase.",
    {"type": "object", "properties": {"text": {"type": "string"}}},
    lambda text: text.upper(),
)
manager = ToolManager([tool])
assert manager.execute(ToolCall("c1", "uppercase", {"text": "agent"})).output == "AGENT"
assert manager.execute(ToolCall("c2", "uppercase", {})).status == "error"
```

参数缺失与业务 ValueError 在当前教学版都归 error。若拆成 `invalid_arguments`，应在 handler 之前做 Schema 校验，否则无法稳定区分 Python TypeError 的来源。不要仅靠错误字符串猜状态。

## L16 参考：Event Sink 设计

最小 sink 是 `Callable[[Event], None]`。`emit()` 先把 Event 加入累计列表，再通知 sink，保证最终 RunResult 有事实记录。sink 抛异常的策略应显式选择：课程建议显示层错误不摧毁核心运行，可捕获并记录 `event_sink_failed`；安全审计 sink 则可能要求 fail closed。两种策略不能默默混用。

```python
def emit(event_type, step, **data):
    event = Event(event_type, len(events) + 1, run_id, step, data)
    events.append(event)
    if event_sink is not None:
        event_sink(event)
```

验证要点：sequence 从 1 连续递增；同一 Run 的 run_id 唯一；第二次运行不复用第一份 events；max_steps 时仍有 `run_completed`。

## 综合故障分析

若第二轮模型报告缺少工具结果，按顺序检查：第一轮 `continuation_items` 是否追加；每个 ToolCall 是否生成 ToolResult；`function_call_output.call_id` 是否与请求一致；output 是否可序列化；第二次 generate 是否收到完整 messages。不要首先修改 Prompt，因为这通常是协议链路问题。

若测试必须构造供应商 SDK 私有对象才能运行，说明 BaseLLM 边界泄漏；若 Tool handler 直接 print 且不返回结果，说明 Observation 无法标准化；若 CLI 只能解析 Runner 的字符串日志，说明 Event 协议缺失。
