# M05 Session 与上下文

## 里程碑目标

让 Agent 支持多轮会话、上下文预算和检查点恢复，同时避免把“不断增长的 messages 列表”误认为完整的长期记忆系统。

## 必须交付

- `SessionStore` 持久化多轮消息，并使用原子写入。
- 每次运行有稳定 `run_id`，会话有独立 `session_id`。
- `ContextWindow` 在预算内选择上下文，保留系统约束和最近任务信息。
- `CheckpointStore` 保存可恢复运行所需的最小状态。
- `Runner.resume(...)` 从检查点继续，而不是从头伪装重跑。

## 概念边界

| 概念 | 负责什么 | 不负责什么 |
| --- | --- | --- |
| Session | 用户多轮交互历史 | 无限制保存所有上下文 |
| Context | 当前模型调用实际输入 | 永久知识存储 |
| Checkpoint | 恢复未完成 run | 替代业务数据库 |
| Memory | 经过选择的长期信息 | 简单复制每条消息 |

## 上下文策略

第一版使用确定性预算与裁剪，优先保证行为可测试。生产系统可进一步增加 token 计数、摘要和检索，但任何压缩都必须保留来源、时间与不可丢失约束。

## 检查点策略

检查点应在稳定边界写入，例如模型响应已解析或工具结果已记录后。恢复时必须避免重复执行已有副作用的工具，并继承原 `run_id` 或建立明确的父子关系。

## 实作任务

1. 使用固定 `session_id` 连续运行两轮并检查落盘消息。
2. 构造超预算上下文，解释哪些消息被保留。
3. 模拟 `max_steps` 后从检查点恢复。
4. 讨论工具执行成功、检查点写入失败时的幂等风险。

## 常见失败

- 把 session、run 和 model turn 使用同一个 ID。
- 每轮把完整历史无限追加给模型。
- 摘要覆盖安全约束或未完成任务。
- 在副作用工具执行前保存“已完成”检查点。
- 恢复时重复执行写文件或命令工具。

## 完成定义

会话可跨进程读取；上下文增长受控；长任务可从检查点继续；恢复行为有离线测试且不会依赖无限消息列表。
