# M05 验收与面试

## 产物验收

- `python -m pytest -q tests/test_session.py tests/test_reliability.py` 通过。
- Session 文件采用 UTF-8 JSON 和原子替换。
- 上下文预算行为可重复测试。
- 检查点包含恢复所需状态和明确 run 标识。

## 代码讲解

展示一条消息从 Session 落盘、Context 选择、Runner 调用到检查点保存的完整路径。说明 Session 历史和本轮 Runtime 事件为什么不应混为一个列表。

## 精选面试题

1. Session、Memory、Context 和 Checkpoint 有何区别？
2. 为什么不能只按消息条数管理上下文？
3. 摘要压缩会引入哪些不可逆信息损失？
4. 检查点应在工具执行前还是后保存？
5. 如何避免恢复任务时重复产生副作用？
6. 原子写入解决了什么，仍未解决什么？

## 故障分析

1. Session JSON 被进程中断写坏，如何恢复和预防？
2. 历史裁剪后模型忘记工作区规则，哪类消息优先级设计有误？
3. 两个进程同时写同一 Session，当前实现可能发生什么？

## 设计取舍题

设计一个从确定性字符预算迁移到 token 预算和摘要压缩的方案，要求保留回滚路径、可观测指标和回归测试。

## 现场任务

新增一个超预算上下文用例，执行 `python -m pytest -q`，并说明为何测试必须固定输入顺序。

## 通过标准

能够用一致性、幂等性和信息预算解释设计，而不把 Session 简化成“把聊天记录存下来”。
