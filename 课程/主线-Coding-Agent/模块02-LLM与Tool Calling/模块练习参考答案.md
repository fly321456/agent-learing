## L05 请求与 Context

`validate_request` 至少检查存在非空 instructions、input 中有 user Message，并且每条 Message 具有合法 role/content。工具观察应作为独立内容加入，而不是伪装成 user 指令。选择历史时只保留与当前目标相关、来源明确、仍然有效的信息。

```python
def validate_request(request: dict) -> None:
    if not request.get("instructions"):
        raise ValueError("instructions are required")
    messages = request.get("input", [])
    if not any(item.get("role") == "user" for item in messages):
        raise ValueError("one user message is required")
```

常见错误是把 Environment 中存在的数据当成模型已看见的数据。测试应直接断言 request，而不是根据最终回答反推。

## L06 文本调用

Fake Client 的价值是记录调用参数。最小测试如下：

```python
client = ScriptedResponsesClient([ScriptedResponse(output_text="ok")])
assert generate_text(client, "m", "rule", "task") == "ok"
assert client.requests[0]["instructions"] == "rule"
assert client.requests[0]["input"] == "task"
```

在线错误应按认证、连接、限流、服务端和响应解析分类，但本课不实现重试。不要打印 API Key，也不要在默认 pytest 中调用网络。

## L07 Tool Schema

`read_file` Schema 应把 path 设为必填字符串、行号设为正整数，并关闭额外属性。Schema 只验证形状，路径是否越界由 Tool 实现负责。

```python
{"type": "function", "name": "calculator",
 "parameters": {"type": "object",
   "properties": {"expression": {"type": "string"}},
   "required": ["expression"], "additionalProperties": False},
 "strict": True}
```

同一响应中的多个调用必须保留各自 `call_id`。不要用工具名称作为关联键，因为同一工具可能被调用两次。

## L08 固定往返

正确顺序是 user input、原始 function call、对应 function call output。非法 JSON 不调用 handler；未知名称回传明确错误；工具异常转换为可解释 output。

```python
assert second_input[1] is original_call
assert second_input[2]["call_id"] == original_call.call_id
```

固定两次实现不应偷偷加入第三轮。让第二个响应再次请求工具时，记录缺陷并在 L09 用 `while` 统一解决。
