# M06 验收与面试

## 产物验收

- `python -m pytest -q tests/test_reliability.py tests/test_tools.py` 通过。
- 暂时性模型错误可重试，确定性错误不盲目重试。
- Trace 可按 `run_id` 与序号还原运行。
- 超时、拒绝、错误和步数上限语义独立。

## 代码讲解

选一个先失败后成功的模型调用，说明 Retry 的边界、事件写入时机和最终 `RunResult`。再选一个命令超时，解释为什么处理策略不同。

## 精选面试题

1. 哪些错误适合重试，哪些不适合？
2. 指数退避为什么通常还要加入随机抖动？
3. Timeout、deadline、cancel 有何区别？
4. Logging、Event、Tracing、Metrics 如何分工？
5. 如何让 Trace 既可调试又不泄漏源码和密钥？
6. 为什么结束原因应该是有限集合而不是异常消息？

## 故障分析

1. Trace 中有 `tool_started` 没有 `tool_finished`，可能发生了什么？
2. 模型重试成功，但计费和延迟异常升高，应新增哪些指标？
3. JSONL 最后一行被截断，读取端应如何降级？

## 设计取舍题

为 Runner 增加总 deadline，说明它如何与模型超时、工具超时、重试退避和人工审批共同工作。

## 现场任务

构造一个不可重试异常，证明调用次数为一次，并执行 `python -m pytest -q`。

## 通过标准

能从故障语义而不是异常字符串制定恢复策略，并能通过 Trace 还原一次失败运行。
