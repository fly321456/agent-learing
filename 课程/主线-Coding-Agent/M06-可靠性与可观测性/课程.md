# M06 可靠性与可观测性

## 里程碑目标

让每次运行的失败步骤、耗时、工具输入输出和结束原因可定位，并对模型暂时性失败、工具超时和配置错误采取不同策略。

## 必须交付

- 错误按配置、模型、协议、工具、审批和超时分类。
- `RetryPolicy` 仅重试允许的模型异常，并采用有界退避。
- Tool 命令有独立超时，Runner 有步骤上限。
- `JsonlTraceWriter` 按事件写入可检索运行记录。
- 配置集中管理，日志与 Trace 不泄漏密钥。
- `RunResult.finish_reason` 与异常分类可对应。

## 代码入口

- `src/agent_from_scratch/errors.py`
- `src/agent_from_scratch/runner.py`
- `src/agent_from_scratch/tracing.py`
- `src/agent_from_scratch/config.py`
- `tests/test_reliability.py`

## 可靠性策略

重试不是“出错就再来一次”。只对短暂网络或限流类模型错误重试；参数错误、审批拒绝、未知 Tool 和确定性代码错误不重试。写工具默认不能靠盲目重试恢复。

超时也分层：模型请求超时、单工具超时、完整 run 截止时间解决不同问题。当前最小实现覆盖模型重试、工具超时和 `max_steps`，后续可增加总 deadline。

## 可观测性

日志服务于人类阅读，事件服务于程序消费，Trace 关联整次运行。最小字段应包含 `run_id`、事件序号、步骤、类型、时间和结构化数据。工具参数可能含源码或秘密，持久化前应支持脱敏策略。

## 实作任务

1. 让 FakeLLM 前两次失败、第三次成功，验证调用次数与退避策略。
2. 执行超时命令，比较 `ToolResult.status` 和 `RunResult.finish_reason`。
3. 写出一次运行的 JSONL Trace，并按 `run_id` 重建顺序。
4. 列出绝不能进入日志的配置字段。

## 自动验证

```powershell
cd agent-from-scratch
python -m pytest -q tests/test_reliability.py tests/test_tools.py
coding-agent --trace .agent-data/trace.jsonl --help
```

## 常见失败

- 对所有异常使用同一个重试装饰器。
- 重试写工具导致重复副作用。
- 只有自然语言日志，没有稳定字段和关联 ID。
- Trace 记录完整环境变量或 API Key。
- 把 Tool 超时、最大步数和模型拒绝都写成 `error`。

## 完成定义

任意离线失败测试都能从结果与 Trace 定位到具体步骤；重试次数有上限；超时与拒绝保持独立语义；敏感配置不会进入输出。
