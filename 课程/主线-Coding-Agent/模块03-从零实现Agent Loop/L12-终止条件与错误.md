# L12 终止条件与错误：Agent 必须知道自己为什么停下

> 建议学习时间：60–90 分钟。本课完成模块 3 最终单文件 Agent，并系统验证失败路径。

## 1. 本节要解决的真实问题

一个只演示成功路径的 Loop 还不能用于工程学习。模型可能给出非法参数、请求未知工具；工具可能抛异常；模型可能永远请求工具。若这些情况都变成 Python 崩溃或模糊空字符串，调用者无法判断任务是否完成。

本课为每条路径定义可观察结果：工具级 status 描述一次行动，Run 级 `finish_reason` 描述整次循环。两者不能混用。

## 2. 前置回顾与问题链

```text
Tool success/error/unknown/invalid → one Tool Result
No tool calls                    → Run completed
Loop budget exhausted            → Run max_steps
```

工具失败后模型仍可能恢复，所以 Tool error 不自动等于 Run error。相反，达到 `max_steps` 时，即使每个 Tool 都成功，目标仍未完成。

## 3. 四类 Tool 状态

`success` 表示处理器正常返回；`invalid_arguments` 表示参数不是对象；`unknown_tool` 表示 Registry 不存在名称；`error` 表示找到并调用处理器，但执行抛异常。

```python
{"call_id": "bad", "name": "calculator", "status": "invalid_arguments"}
{"call_id": "missing", "name": "missing_tool", "status": "unknown_tool"}
{"call_id": "broken", "name": "broken", "status": "error", "error": "boom"}
```

明确分类能让下一轮模型调整，也能让测试定位责任边界。

## 4. 两类 Run 终止

教学版当前有 `completed` 与 `max_steps`。Completed 要求模型返回无 Tool Call 的响应；max_steps 表示预算耗尽，answer 保持空字符串，不能伪装成功。

正式 Runtime 还会有 denied 和 error，但本课不提前扩展。未知 Tool 是 Observation，脚本模型可以下一轮给出解释，因此最终仍可能 completed。

## 5. 案例一：失败后完成

模型同轮请求非法 calculator、未知工具和会抛错的 broken。Runtime 生成三个结果，第二轮模型看到它们后回答“errors observed”。Run 的 finish_reason 是 completed，但 Tool Results 仍保留失败。

这说明“Run 完成”不等于“所有行动成功”，而表示协议正常走到最终响应。答案质量与任务是否真正解决，需要模块 7 的评测判断。

## 6. 案例二：所有工具成功但 Run 未完成

模型重复请求 ping，每次都返回 pong，却从不输出最终文本。`max_steps=2` 后运行停止：两个 Tool success，Run finish_reason=max_steps。没有硬上限时会无限消耗调用、时间和费用。

### 误区一：异常都抛到最外层最简单

可恢复工具错误会中断闭环，模型没有机会换路。协议错误应先标准化为 Observation。

### 误区二：有任何文本就算完成

模型可能在请求 Tool 时附带解释文字。课程以 Tool Call 是否为空判断，不靠 content 猜测。

## 7. 完整运行轨迹

```text
Task: stop safely
Step 1 ToolCall missing → unknown_tool
Step 2 ToolCall missing → unknown_tool
Loop budget exhausted
answer=''
steps=2
finish_reason=max_steps
```

恢复场景则是错误 Observation 后，下一轮无 Tool Call，finish_reason=completed。

## 8. 模块最终完整代码结构

最终源码位于 [agent_loop.py](../../../agent-from-scratch/course-checkpoints/03-agent-loop/agent_loop.py)，Demo 位于 [demo.py](../../../agent-from-scratch/course-checkpoints/03-agent-loop/demo.py)。核心由四部分组成：

```python
@dataclass
class ToolCall:
    id: str
    name: str
    arguments: Any

@dataclass
class ModelResponse:
    content: str = ""
    tool_calls: list[ToolCall] = field(default_factory=list)

class ScriptedModel:
    def generate(self, items, tools) -> ModelResponse: ...

def execute_tool(call, tools) -> dict: ...
def run_agent(task, model, tools, max_steps=5) -> dict: ...
```

完整实现约百余行，仍保持单文件，便于从上到下讲清。模块 4 才拆成正式包。

## 9. 逐段解释与接口边界

`ToolCall` 描述模型请求；`ModelResponse` 描述一次模型调用；`execute_tool` 描述一次行动；`run_agent` 描述整次运行。即使都用字典返回，也要先在概念上分层。

`ScriptedModel.requests` 保存输入快照，使测试能证明 Observation 进入下一轮。`trace` 记录模型步骤，`tool_results` 记录行动结果，`answer` 和 `finish_reason` 记录终态。
