## 故障注入

分别制造非法 arguments、未知 name、handler 异常和无限重复 Tool Response。检查每次的 Tool status、Run finish_reason、steps 和 Trace，不允许 Python 未捕获异常代替协议结果。

## 代码讲解

从 `run_agent` 输入讲到返回，说明 items 为什么在循环外、为何先处理整轮 Tool、结果如何回传、什么条件 completed、什么条件 max_steps。再解释为什么模块 4 才拆包。

## 精选面试题

1. Function Calling 与 Agent Loop 有什么区别？
2. Tool Registry 降低了哪种耦合？
3. 同轮多 Tool 为什么不等于并发？
4. Tool error 后 Run 为什么仍可能 completed？
5. 所有 Tool success 为什么仍可能 max_steps？
6. 如何证明 Observation 确实进入下一轮？

## 通过标准

五个入口与专项测试通过；能够讲清两层循环和四种 Tool 状态；能够定位四类故障并恢复。通过后进入 Runtime 模块化重构。
