# M01 运行基线

## 里程碑目标

把仓库从“若干 Python 脚本”升级为可安装、可离线验证、可按需调用真实模型的标准项目。完成后，学习者应能解释依赖、配置、模型适配层和测试替身之间的边界。

## 必须交付

- `pyproject.toml` 能以 editable 模式安装项目。
- 业务代码位于 `src/agent_from_scratch/`，测试位于 `tests/`。
- `BaseLLM.generate(...) -> LLMResponse` 是 Runtime 依赖的唯一模型接口。
- `OpenAILLM` 封装供应商 SDK，`FakeLLM` 支持完全离线测试。
- 默认测试不读取 `OPENAI_API_KEY`，在线调用必须显式触发。

## 代码入口

- `agent-from-scratch/pyproject.toml`
- `agent-from-scratch/src/agent_from_scratch/config.py`
- `agent-from-scratch/src/agent_from_scratch/llm.py`
- `agent-from-scratch/src/agent_from_scratch/schemas.py`
- `agent-from-scratch/tests/test_runner.py`

## 核心设计

### 标准包结构

`src` 布局避免测试误导入工作目录中的同名文件。安装后，CLI、测试和使用者导入的是同一个包。

### 配置边界

配置层只负责从参数和环境变量构造不可变配置，不在模块导入时偷偷读取密钥或发起网络请求。模型名是部署配置，不是课程里的永久常量。

### LLM 适配层

Runtime 只认识 `LLMResponse`。OpenAI 的原始对象可以用于调试，但 Agent Loop 不允许读取其内部字段；供应商续写信息通过 `continuation_items` 不透明传递。

### 离线优先

`FakeLLM` 返回预设响应，使纯文本、工具调用和异常路径都可重复测试。真实 API 只做人工烟雾测试，不能成为默认验收条件。

## 实作任务

1. 阅读 `pyproject.toml`，说明 build backend、依赖组和 console script 的作用。
2. 阅读 `BaseLLM`、`OpenAILLM`、`FakeLLM`，画出供应商 SDK 到 Runtime 协议的转换边界。
3. 新增一个不依赖网络的 LLM 测试替身场景。
4. 在没有 API Key 的终端执行完整测试。

## 常见失败

- 从仓库根目录直接导入旧脚本，掩盖 `src` 包未安装的问题。
- 在 `BaseLLM` 中暴露 OpenAI 专属类型，导致 Runner 被供应商绑定。
- 把密钥写进源码、示例或测试快照。
- 把某个模型名写成永远正确的默认选择。

## 完成定义

全新环境可安装项目；无网络时全部离线测试通过；只有显式提供密钥并执行人工命令时才产生真实 API 请求。
