# M04 验收与面试

## 产物验收

- `python -m pytest -q tests/test_runner.py tests/test_cli.py` 通过。
- `RunResult` 保留全部事件和工具结果。
- 每个事件都有稳定序号、`run_id` 和步骤号。
- Runner 未读取供应商 `raw_response`。

## 代码讲解

选一次“模型请求工具后给出最终答案”的运行，分别指出两个 `LLMResponse`、一个 `ToolResult` 和最终 `RunResult`。说明 `continuation_items` 为什么是不透明字段。

## 精选面试题

1. `LLMResponse` 与 `RunResult` 为什么不能复用同一个类型？
2. Event 与日志有什么区别？
3. 事件序号和时间戳分别解决什么问题？
4. 为什么 `raw_response` 可保留却不属于稳定接口？
5. Structured Outputs 与 Runtime 结构化结果有什么区别？
6. 流式事件应该推送增量还是每次推送完整快照？

## 故障分析

1. CLI 显示工具执行成功，但 `RunResult.tool_results` 为空，状态在哪一层丢失？
2. 重试模型调用后出现重复事件，事件生成时机应如何调整？
3. 前端依赖供应商专属字段后无法切换模型，如何设计迁移？

## 设计取舍题

比较“事件列表随 `RunResult` 一次返回”和“异步事件流 + 最终结果”两种接口。讨论背压、恢复、顺序、测试和 CLI 复杂度。

## 现场任务

给完整运行增加一个事件顺序断言，执行 `python -m pytest -q`，并解释为什么不能只断言事件数量。

## 通过标准

能清楚解释三层协议、供应商隔离和事件语义，并从测试中证明整次运行信息没有丢失。
