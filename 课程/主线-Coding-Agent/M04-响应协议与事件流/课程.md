# M04 响应协议与事件流

## 里程碑目标

建立模型调用、工具执行和整次运行三个层次的稳定协议，并让 CLI 能展示完整过程而不是只打印最终字符串。

## 必须交付

- `LLMResponse` 只描述一次模型调用。
- `ToolResult` 只描述一次工具执行。
- `RunResult` 描述完整运行，包含内容、事件、工具结果、步数和结束原因。
- `Event` 具有类型、顺序号、`run_id`、步骤号和数据。
- 事件在整次运行中累计，序号稳定递增。
- Runner 只读取 `continuation_items`，不读取 `raw_response.output`。

## 三层协议

| 层次 | 类型 | 生命周期 | 典型字段 |
| --- | --- | --- | --- |
| 模型调用 | `LLMResponse` | 单次 LLM 请求 | content、tool_calls、continuation_items |
| 工具执行 | `ToolResult` | 单次 ToolCall | status、output、error、duration |
| Agent 运行 | `RunResult` | 完整 run | content、events、tool_results、steps、finish_reason |

模型的 JSON Schema 结构化输出是业务内容约束；`RunResult` 是 Runtime 协议。两者不能混为一层。

## 事件设计

事件用于 CLI 展示、Tracing、调试和未来流式消费。核心事件至少覆盖 run 开始、模型调用、工具开始、工具结束和 run 结束。事件数据应可 JSON 序列化，且不能依赖 UI 专属 `Block`。

## 常见失败

- 用 `LLMResponse` 表示整次 Agent 运行。
- 事件序号在每个步骤重新从零开始。
- 只保留最后一轮工具结果。
- 核心协议提前加入只服务某个前端的空字段。
- Runner 穿透抽象读取供应商 SDK 对象。

## 完成定义

调用者仅凭 `RunResult` 就能重建运行摘要和工具过程；更换 LLM 适配器不需要修改 Runner；CLI 不需要解析供应商对象。
