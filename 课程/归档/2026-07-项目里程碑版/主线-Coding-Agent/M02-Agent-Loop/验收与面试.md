# M02 验收与面试

## 产物验收

- `python -m pytest -q tests/test_runner.py tests/test_tools.py` 通过。
- 纯文本、单 Tool、多 Tool、未知 Tool 和最大步数均有离线测试。
- Runner 返回明确 `finish_reason`，不返回裸字符串。

## 代码讲解

从用户输入开始，逐行说明 `Runner.run` 如何调用 LLM、解析 ToolCall、执行工具、回送结果并结束。讲解中必须区分模型决策、Runtime 编排和 Python 工具执行。

## 精选面试题

1. Agent、Runner、LLM、ToolManager 各自应该知道什么、不应该知道什么？
2. Tool Calling 为什么不是“模型调用了函数”？
3. 同一轮返回多个 ToolCall 时，串行与并行执行如何取舍？
4. 为什么必须有 `max_steps`？它与超时有什么不同？
5. 未知 Tool 应该回送模型还是立即结束？本项目如何选择？
6. Tool 参数是合法 JSON，但不符合函数签名，错误属于哪一层？

## 故障分析

1. Agent 在第二轮重复调用同一写工具，如何定位是提示词、续写数据还是状态管理问题？
2. Tool 已成功但模型看不到结果，应检查哪些消息和调用标识？
3. 多 Tool 时只有最后一个结果保留，最可能的状态错误是什么？

## 设计取舍题

设计“遇到一个 Tool 失败后，剩余同轮 Tool 是否继续执行”的策略。答案需要讨论副作用、依赖关系、可观测性和恢复方式。

## 现场任务

新增一个未知工具场景，先写失败测试，再让 `python -m pytest -q` 通过，并解释为什么没有用宽泛异常吞掉问题。

## 通过标准

能画出状态机、解释全部终止分支，并用测试证明 Loop 不会无限运行。
