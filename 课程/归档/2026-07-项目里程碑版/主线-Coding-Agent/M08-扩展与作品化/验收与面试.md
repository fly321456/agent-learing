# M08 验收与面试

## 产物验收

- `python -m pytest -q`、`coding-agent --help`、`coding-agent-eval` 均成功。
- 离线示例无需密钥和网络。
- MCP 可选依赖安装后能创建 `FastMCP` server。
- README 明确安全边界、在线费用和旧脚本状态。
- Web、RAG、多 Agent 没有被伪装成主线已交付能力。

## 作品讲解

用 10 分钟回答：项目解决什么问题、架构如何分层、如何保证工具安全、如何恢复与追踪、怎样测试和评测、当前限制是什么。演示失败路径与测试证据，不只演示成功答案。

## 精选面试题

1. 为什么主线选择 CLI 而不是先做 Web？
2. MCP 标准化了什么，没有标准化什么？
3. 如何避免 MCP adapter 与本地 Tool 出现双实现？
4. 什么条件下 RAG 能改善 Coding Agent？
5. 什么条件下多 Agent 的收益大于通信与治理成本？
6. 如何让招聘者在 15 分钟内验证这个作品不是 Demo？

## 故障分析

1. MCP stdio 客户端握手失败但服务没有异常，为什么应检查 stdout？
2. 可编辑安装能跑，打包后缺少评测数据，项目配置可能缺什么？
3. CLI 运行成功但无法复盘工具过程，哪项作品证据缺失？

## 设计取舍题

从 Web 工作台、RAG、多 Agent 三个方向中选择一个作为下一阶段，必须用 20 题评测数据、用户工作流和维护成本论证；“技术更热门”不构成理由。

## 现场任务

在空终端按 README 运行离线示例和 `python -m pytest -q`，然后选择一个失败测试解释定位路径。

## 通过标准

项目可复现、设计可解释、失败可定位、指标可比较；能够坦诚说明尚未实现的能力及其进入条件。
