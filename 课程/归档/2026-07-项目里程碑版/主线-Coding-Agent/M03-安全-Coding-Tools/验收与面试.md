# M03 验收与面试

## 产物验收

- `python -m pytest -q tests/test_tools.py tests/test_e2e_coding_tools.py` 通过。
- 读取、搜索、修改、命令四类工具共享同一工作区上下文。
- 写入和执行在无审批时返回 `denied`。
- 越界路径和命令超时分别有测试。

## 代码讲解

演示 `_workspace_path`、`ToolSpec.risk`、审批回调和 `subprocess.run(..., shell=False)` 如何组成安全边界，并指出哪些风险仍需操作系统沙箱解决。

## 精选面试题

1. 为什么 `startswith(workspace)` 不能安全验证路径？
2. `resolve()` 能解决哪些问题，不能解决哪些问题？
3. 为什么命令工具优先接收 argv 数组？
4. 审批应该绑定工具名称、参数，还是最终系统调用？
5. 精确文本替换与统一 diff 补丁各有什么取舍？
6. ToolResult 为什么要区分 `denied`、`timeout` 和 `error`？

## 故障分析

1. 补丁报告成功但测试仍读取旧代码，如何排查工作目录和文件编码？
2. Windows 上命令可以启动但无法结束，超时后还需考虑什么？
3. 搜索工具扫描到 `.git` 或大型构建目录，会产生哪些可靠性问题？

## 设计取舍题

如果要把项目用于不可信仓库，说明应用层工作区限制、容器或虚拟机沙箱、系统权限、网络隔离分别承担什么责任。

## 现场任务

为一个重复出现的 `old_text` 写测试，证明未设置 `replace_all` 时补丁拒绝歧义修改，然后执行 `python -m pytest -q`。

## 通过标准

能明确区分“产品审批”“代码路径校验”“操作系统隔离”，不会把 Prompt 当作安全机制。
