# Lesson8：Memory 写入策略与检索注入初版 - 面试题整理

## 1. 为什么说 Memory 系统难的不是“存”，而是“写入策略”和“注入策略”？

### 参考答案

因为单纯提供一个存储容器并不难，难的是：

1. 什么信息值得进入长期记忆
2. 什么时候写入最合适
3. 当前任务需要读取哪些记忆
4. 读取后如何以合适的形式注入模型

如果这些策略没有设计好，就会出现两种常见问题：

- 存了很多，但都是噪音
- 读了很多，但对当前推理没帮助

所以 Memory 的工程难点不在“有没有地方存”，而在“记忆如何进入运行闭环”。

---

## 2. 为什么“有信息就存、每次都全读”通常是错误的第一版 Memory 方案？

### 参考答案

因为这样会同时制造两个问题。

### 第一，写入噪音

会把大量临时中间过程、未验证猜测、一次性 Tool 输出都塞进长期 Memory。

### 第二，读取噪音

每次都全量注入会导致：

- prompt 变长
- 当前任务重点被稀释
- 模型注意力分散

结果是 Memory 反而拖累了 Agent，而不是帮助 Agent。

---

## 3. 一个好的 Memory 系统为什么要做到“记得准、取得准、喂得准”？

### 参考答案

这是因为长期记忆的价值不在“数量”，而在“相关性和可用性”。

### 记得准

表示只沉淀稳定、高价值、可复用的信息。

### 取得准

表示只取出和当前任务相关的记忆。

### 喂得准

表示把相关记忆以简洁、结构化、适量的方式注入模型。

只有这三步同时成立，Memory 才真正对 Agent 有用。

---

## 4. 第一版长期 Memory 更适合写入哪些信息？

### 参考答案

第一版更适合写入：

1. 用户稳定偏好
2. 项目级稳定事实
3. 已验证的关键结论

例如：

- 用户希望中文回答
- 当前项目是 SpringBoot + Redis + MySQL
- 订单主流程在 `OrderService`

这些信息都满足稳定、高价值、可复用的特点。

---

## 5. 为什么“每轮自动写 Memory”通常是坏设计？

### 参考答案

因为每一轮都有大量临时性信息，例如：

- 试探性推理
- 尚未验证的判断
- 一次性中间结果
- 过渡步骤

如果每轮自动写入，长期 Memory 很快就会被污染，检索质量下降，系统后续更难用。

所以长期记忆的写入应该是：

> **稀疏的、选择性的、基于稳定结论的。**

---

## 6. 第一版 Memory 比较合理的写入触发时机有哪些？

### 参考答案

第一版通常可以先使用三类触发时机：

1. 任务阶段结束后
2. 稳定事实被确认时
3. 用户偏好被明确表达时

这些时机的共同特点是：

> **信息已经比较稳定，后续复用价值比较高。**

---

## 7. 为什么读取策略往往比写入策略更直接影响模型效果？

### 参考答案

因为最终模型看到的，是“被注入的那部分信息”。

即使存得很好，如果读取时：

- 不做相关性判断
- 不限制数量
- 不整理格式

那么这些记忆仍然会变成新的上下文噪音。

所以对模型效果来说，Memory 的实际使用质量往往更依赖读取和注入策略。

---

## 8. 为什么长期 Memory 不应该全量回灌到每一次推理里？

### 参考答案

因为全量回灌会带来几个明显问题：

1. Prompt 长度增加
2. 当前任务重点被稀释
3. 模型注意力分散
4. Token 成本上升

很多长期记忆虽然有价值，但并不一定和当前任务相关。

所以更合理的原则是：

> **按任务相关性选择性注入，而不是无差别全量回灌。**

---

## 9. 第一版 Memory 注入为什么更适合整理成独立的 memory context？

### 参考答案

因为直接把原始记忆散乱拼回消息流，通常不利于模型理解，也不利于长度控制。

整理成结构化的 memory context，例如：

```text
Relevant memory:
- ...
- ...
```

有几个好处：

1. 结构清晰
2. 长度更容易控制
3. 更容易和 system prompt、session summary 分离

所以 Memory 注入不是“原样回放”，而是“检索后结构化组装”。

---

## 10. `MemoryStore`、`Runner`、Prompt 组装层在 Memory 注入中分别负责什么？

### 参考答案

### `MemoryStore`

负责：

- 存储和查询记忆

### `Runner`

负责：

- 决定当前时机是否需要读取记忆
- 决定取哪类记忆

### Prompt 组装层

负责：

- 把记忆整理成模型易消费的上下文片段

因此更清晰的职责划分是：

> **MemoryStore 管数据，Runner 管时机，Prompt 层管注入格式。**

---

## 11. 第一版没有向量检索，也能做出合理的 Memory 系统吗？

### 参考答案

可以。

因为第一版更重要的是先把结构搭对：

1. 有清晰的记忆分类
2. 有写入筛选标准
3. 有读取时机判断
4. 有结构化注入方式

如果这些都没有，就算加上 embedding 和向量检索，系统也不一定好用。

所以第一版的重点是工程结构正确，而不是检索技术复杂。

---

## 12. 为什么说 Memory 的关键是“进入运行闭环”？

### 参考答案

因为很多系统虽然保存了大量历史信息，但这些信息并没有在真正需要的时候被正确使用。

一个真正有效的 Memory 系统必须形成闭环：

1. 运行中产生高价值信息
2. 稳定信息被写入长期记忆
3. 新任务开始时检索相关记忆
4. 相关记忆被整理后重新参与推理

只有这样，Memory 才不是静态仓库，而是 Agent 运行机制的一部分。

---

## 13. 面试时如何简洁总结这一课？

### 参考答案

可以这样回答：

> Memory 系统真正难的不是存储，而是写入策略和注入策略。工程上不能“有信息就存、每次都全读”，否则长期记忆会变成噪音源。更合理的做法是只在稳定、高价值、可复用的信息出现时写入，并在后续任务中按相关性选择性检索，再以结构化 memory context 的形式注入模型。
