# Lesson17：最小 RAG 接入与知识外置初版 - 面试题整理

## 1. 为什么不是所有知识都应该塞进 Prompt？

### 参考答案

因为 Prompt 更适合表达：

- 角色
- 行为规则
- 工具使用约束
- 输出风格

而不适合承载大量外部知识材料。

如果把过多背景资料长期塞进 Prompt，会带来：

1. Prompt 过长
2. 相关性差
3. 知识更新成本高

所以 Prompt 适合做规则层，而不是大规模知识仓库。

---

## 2. 为什么也不能把所有外部知识都塞进长期 Memory？

### 参考答案

因为长期 Memory 更适合保存：

- 稳定偏好
- 高价值事实
- 已验证结论
- 可跨会话复用的信息

如果把外部知识无差别全部沉淀进去，Memory 会：

- 失去高价值筛选特性
- 噪音变大
- 相关性下降
- 更新治理困难

所以外部知识通常更适合按需检索，而不是一股脑存进内部长期记忆。

---

## 3. RAG 的本质是什么？

### 参考答案

RAG 的本质不是“接一个向量库”，而是：

> **把知识从上下文里外置，并在需要时按相关性取回。**

也就是说，它首先是一个知识组织与使用策略问题，而不是单纯的向量检索技术问题。

---

## 4. 什么叫“知识外置”？

### 参考答案

知识外置指的是：

> **把原本可能塞进 Prompt、Memory 或长上下文中的知识，放到 Agent 外部的独立知识源里。**

然后在当前任务真正需要时，再把相关片段取回来注入上下文。

这让知识不再一直背在模型身上，而是变成按需访问的外部资源。

---

## 5. 为什么 RAG 在 Agent 里比在普通聊天里更重要？

### 参考答案

因为在普通聊天里，RAG 更多是帮助模型回答得更有依据。

但在 Agent 里，外部知识不仅影响答案内容，还会影响：

- 下一步怎么做
- 该不该调用 Tool
- 哪个方向优先探索
- 是否已经具备下结论的条件

所以在 Agent 中，RAG 更像一个：

> **外部知识驱动的决策辅助层。**

---

## 6. 第一版最小 RAG 系统先要解决什么问题？

### 参考答案

第一版不需要一开始就追求高级检索技术。

最重要的是先打通最小链路：

1. 有外部知识源
2. 能根据当前任务取回相关内容
3. 能把相关内容注入当前上下文

也就是说，第一版先解决“知识接入链是否打通”，而不是“检索技术是否最先进”。

---

## 7. 为什么第一版 RAG 更适合先学检索流程，而不是先学向量技术？

### 参考答案

因为 RAG 的主干不是某一种检索算法，而是完整的信息流转链：

1. 知识如何存放
2. 查询如何形成
3. 内容如何召回
4. 召回内容如何整理
5. 如何与 Prompt / Session / Memory 结合

如果这条链本身不清楚，即使接入向量库，效果也不一定稳定。

所以学习顺序上，应该先掌握流程，再深入技术细节。

---

## 8. 一个最小 RAG 流程通常长什么样？

### 参考答案

最小流程通常可以理解为：

1. 判断当前任务是否需要外部知识
2. 生成检索请求
3. 从知识源找相关片段
4. 整理成 `knowledge context`
5. 与 Prompt / Session / Memory 一起送给模型

这就是最小可运行的 RAG 闭环。

---

## 9. 为什么“是否需要检索”本身就是一个决策点？

### 参考答案

因为不是每一个任务都需要外部知识。

例如：

- 查询当前时间
- 继续当前会话里已经清楚的任务
- 执行简单本地 Tool

这些场景如果每轮都检索，只会增加：

- 成本
- 延迟
- 噪音

所以检索不应该是默认动作，而应该是按需动作。

---

## 10. 为什么检索出来的知识不能原样全塞进上下文？

### 参考答案

因为召回“相关”不等于全部内容都对当前任务有价值。

原样全塞会带来：

1. 上下文再次膨胀
2. 重点被淹没
3. Session 目标被无关细节稀释

所以 RAG 不是检索完就结束，而是还需要把知识整理成可消费的上下文片段。

---

## 11. `knowledge context` 和原始知识片段有什么区别？

### 参考答案

原始知识片段更多只是“被召回的内容”。

而 `knowledge context` 是：

> **经过筛选、组织、结构化之后，真正准备用来参与模型推理的知识输入。**

它通常会更短、更聚焦，也更强调：

- 关键点
- 来源
- 与当前任务的相关性

所以这两者不是同一个层次。

---

## 12. RAG 和 Memory 的分工怎么理解？

### 参考答案

可以这样区分：

### Memory

更偏：

> Agent 内部运行过程中沉淀下来的高价值内生记忆

例如：

- 用户偏好
- 已验证项目事实
- 任务历史结论

### RAG

更偏：

> 当前任务需要时，从外部知识源临时取回的知识

例如：

- 外部文档
- 产品说明
- API 规范
- FAQ

一句话总结：

> **Memory 是内生记忆，RAG 是外取知识。**

---

## 13. 为什么第一版 RAG 的重点不是“检索绝对正确”，而是“知识接入链打通”？

### 参考答案

因为在系统早期阶段，最大的瓶颈通常不是检索算法，而是：

- 是否有知识源
- 是否能形成检索请求
- 是否能把结果带回上下文
- 是否能与当前 Agent 运行结构融合

如果这条链路都没打通，谈检索优化没有意义。

所以第一版的目标更偏向：

> **建立最小可用接入能力。**

---

## 14. 为什么说 RAG 是 Agent 规模化获取知识的基础设施？

### 参考答案

因为一旦知识量变大，Prompt 和 Memory 都不适合承担海量外部知识。

这时必须有一种机制能做到：

- 知识外置
- 按需取回
- 动态注入

RAG 正是解决这一层问题的。

所以它不是一个“高级增强功能”，而是当 Agent 需要处理规模化知识时的重要基础设施。

---

## 15. 面试时如何简洁总结这一课？

### 参考答案

可以这样回答：

> RAG 的核心不是接一个向量库，而是把知识从上下文里外置，并在当前任务需要时按相关性取回。Prompt 更适合规则层，Memory 更适合高价值内部记忆，而外部文档、FAQ、规范等知识更适合走 RAG。工程上第一版最重要的是先打通知识接入链，而不是一开始就沉迷检索算法细节。
