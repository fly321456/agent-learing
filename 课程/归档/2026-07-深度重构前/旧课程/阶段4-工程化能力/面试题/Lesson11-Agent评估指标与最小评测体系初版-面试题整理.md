# Lesson11：Agent 评估指标与最小评测体系初版 - 面试题整理

## 1. 为什么 Agent 项目一定要建立评估体系？

### 参考答案

因为如果没有评估体系，Agent 的优化就很容易停留在主观感受层面。

例如你可能：

- 改了 Prompt
- 改了 Tool Schema
- 增加了 Memory
- 重构了上下文组织

但如果没有固定评测方法，你无法判断：

- 是不是真的变好了
- 哪个维度变好了
- 有没有引入新的回归问题

所以评估体系的价值在于：

> **让 Agent 的迭代从“凭感觉”变成“可比较、可量化、可回归”。**

---

## 2. 为什么说“没有评估，Agent 优化很容易退化成主观感受管理”？

### 参考答案

因为没有评估时，开发者通常只能靠：

- 自己手动问几个问题
- 看个别演示效果
- 依赖直觉判断这次是不是更好了

这些方式都不稳定，也不可重复。

结果就是：

- 优化是否有效说不清
- 回归问题不容易发现
- 不同方案之间无法客观比较

所以没有评估，所谓“优化”常常只是主观印象，而不是工程事实。

---

## 3. Agent 评估和普通函数测试最本质的区别是什么？

### 参考答案

普通函数测试通常是确定性输入输出关系，例如：

```python
add(1, 2) == 3
```

而 Agent 的输出往往不是严格确定的。

同一个任务可能存在：

- 多种合理表达
- 多种合理 Tool 路径
- 不同但都可接受的中间过程

所以 Agent 评估通常不会只做“字符串完全匹配”，而更关注：

- 任务是否完成
- Tool 路径是否合理
- 最终结果是否满足目标

因此：

> **Agent 评估更偏任务级评估，而不是文本级断言。**

---

## 4. 第一版 Agent 评估体系最应该先关注哪些维度？

### 参考答案

当前阶段最适合先关注四类维度：

1. 任务完成率
2. Tool 调用正确率
3. 输出质量
4. 运行效率

其中任务完成率是第一优先级，因为 Agent 的核心价值首先是“能把任务做成”。

---

## 5. 为什么任务完成率通常是 Agent 第一指标？

### 参考答案

因为无论回答多漂亮、推理多丰富，如果任务本身没有完成，系统的核心价值就没有实现。

例如：

- 没有真正读到文件
- 没有正确调用 Tool
- 没有完成用户目标

这些情况下，即使语言表达很好，也不能算成功。

所以评估 Agent 时，第一步永远是先问：

> **任务到底完成了没有。**

---

## 6. 为什么 Agent 评估不能只看“最后答案对不对”？

### 参考答案

因为 Agent 不只是结果系统，还是过程系统。

很多时候最终答案虽然对，但中间可能存在严重工程问题，例如：

- 调了很多不必要的 Tool
- 花了太多轮才完成
- 成本太高
- Memory 注入混乱

反过来，有时最终答案接近正确，但路径明显错误，说明系统仍不稳定。

所以 Agent 评估必须至少同时关注：

- 结果正确性
- 路径合理性
- 运行效率

---

## 7. 为什么“固定样例集”比“展示一个成功 Demo”更有工程价值？

### 参考答案

因为单个成功 Demo 很容易被挑选出来，不能代表系统整体稳定性。

而固定样例集的价值在于：

- 每次优化后都能重复验证
- 能做前后版本对比
- 能发现回归
- 能覆盖多种任务类型

所以从工程角度看：

> **固定样例集提供的是可比较性，而单次 Demo 只提供展示性。**

---

## 8. 第一版评测集为什么更适合“小而稳”，而不是一开始就“大而全”？

### 参考答案

因为当前阶段最重要的是先建立评估闭环，而不是追求评测平台复杂度。

小而稳的评测集有几个优点：

1. 容易维护
2. 容易重复执行
3. 更适合快速迭代
4. 足以发现明显回归问题

所以第一版更适合从 10 到 15 个代表性样例开始，而不是一上来就追求几百个案例。

---

## 9. 一个最小可用的 Agent Eval Set 通常应包含哪几类任务？

### 参考答案

当前阶段可以先分成三组：

### A 组：基础能力任务

验证：

- 单 Tool 调用是否稳定

### B 组：多轮任务

验证：

- Agent Loop 是否稳定
- 多步任务链路是否合理

### C 组：易错任务

验证：

- 是否存在误调用 Tool
- 是否容易被无关上下文或记忆干扰

这种分组非常适合作为第一版最小评测集。

---

## 10. 为什么第一版评估不一定要完全自动化？

### 参考答案

因为当前阶段更重要的是先建立：

- 固定样例
- 固定观察维度
- 固定记录方式

哪怕第一版先用人工判断和 Markdown 表格，也已经比“凭感觉判断”强很多。

自动化平台当然重要，但应该建立在评估结构已经清晰的基础上。

所以第一版的重点是：

> **先做到稳定可比较，再逐步自动化。**

---

## 11. 第一版最小指标通常可以定义哪些？

### 参考答案

当前阶段很适合先定义下面这些最小指标：

1. `Task Success Rate`
2. `Tool Selection Accuracy`
3. `Unnecessary Tool Call Rate`
4. `Average Turns`
5. `Average Runtime`
6. `Obvious Failure Count`

这组指标已经可以覆盖：

- 任务完成情况
- Tool 使用情况
- 运行效率
- 明显失败情况

足够支撑第一版迭代。

---

## 12. 为什么“回归评测”是 Agent 工程里的关键动作？

### 参考答案

因为 Agent 系统常常是多模块联动的，一个小改动可能影响多个能力维度。

如果不做回归评测，就很容易出现：

- 修好了一个问题
- 却悄悄破坏了另外两个能力

回归评测的价值在于：

- 验证优化是否真的有效
- 发现新增回归
- 保持稳定迭代节奏

所以工程化开发里，重要改动后重新跑固定评测集，是非常核心的动作。

---

## 13. 为什么说评估体系本质上是在给 Agent 建立反馈闭环？

### 参考答案

因为 Agent 开发不是一次性完成，而是持续迭代的。

而迭代要有效，必须知道：

- 改动后发生了什么变化
- 哪个指标提升了
- 哪个指标变差了
- 下一个优化重点是什么

评估体系正是把这些变化显式化、可比较化。

所以它本质上是：

> **开发行为和系统结果之间的反馈回路。**

---

## 14. 如果让你设计一个最小版 Agent 评测体系，你会怎么做？

### 参考答案

我会先做四件事：

1. 建一个固定样例集，覆盖基础任务、多轮任务和易错任务
2. 为每个样例定义观察字段，例如任务是否完成、Tool 是否正确、轮数、耗时、备注
3. 每次关键改动后都回归跑这组样例
4. 把结果记录成表格，便于不同版本对比

第一版不必很自动化，但必须稳定可重复。

---

## 15. 面试时如何简洁总结这一课？

### 参考答案

可以这样回答：

> Agent 项目必须建立评估体系，否则优化很容易停留在主观感受层面。相比普通函数测试，Agent 更适合做任务级评估，重点看任务完成率、Tool 调用正确率、输出质量和运行效率。工程上通常从固定样例集和最小指标开始，逐步建立回归评测能力，这样系统才能稳定迭代。
