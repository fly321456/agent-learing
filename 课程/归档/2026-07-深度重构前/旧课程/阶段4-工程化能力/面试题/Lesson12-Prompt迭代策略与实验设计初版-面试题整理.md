# Lesson12：Prompt 迭代策略与实验设计初版 - 面试题整理

## 1. 为什么说 Prompt 迭代不是写作活动，而是实验活动？

### 参考答案

因为 Prompt 在 Agent 系统里不是普通文案，而是会直接影响系统行为的控制接口。

你每改一句 Prompt，都可能影响：

- 任务目标理解
- Tool 调用倾向
- 风险偏好
- 输出结构

因此 Prompt 优化不能只靠“写得顺不顺”，而应该像实验一样：

- 有问题定义
- 有改动假设
- 有对照样例
- 有评估结果

所以更准确地说，Prompt 迭代本质上是系统行为实验。

---

## 2. 为什么 Prompt 优化最容易失控？

### 参考答案

因为 Prompt 很容易改，而且改完后经常“看起来有效”。

常见失控方式包括：

1. 发现一个问题就补一条规则
2. 一次改很多地方，失去归因能力
3. 只看少量演示，不做固定评测
4. Prompt 越写越长，规则开始冲突

所以 Prompt 优化最大的问题不是“难改”，而是太容易在没有实验纪律的情况下越改越乱。

---

## 3. 为什么 Prompt 改动不能一次改很多内容？

### 参考答案

因为一旦一次改了很多变量，例如：

- 改角色定义
- 改 Tool 规则
- 加示例
- 改输出格式

最后即使效果变化了，你也无法知道到底是哪一项起了作用。

这会直接失去归因能力。

所以最基础的实验纪律是：

> **一次只改一个明确变量。**

这样才能做有效对照。

---

## 4. Prompt 迭代前为什么要先明确“问题现象”和“怀疑原因”？

### 参考答案

因为如果没有问题定义，Prompt 修改就会退化成盲改。

更工程化的方式是先明确：

1. 当前具体出什么问题
2. 怀疑哪一段 Prompt 导致了这个问题
3. 准备改哪一处来验证假设

这样做的价值是：

- 让改动更聚焦
- 让结果更容易解释
- 避免“感觉不够好就随便改”

---

## 5. 一个最小 Prompt 实验模板通常应包含哪些部分？

### 参考答案

最小模板通常可以包含：

1. 问题描述
2. 假设
3. 改动内容
4. 验证样例
5. 观察指标
6. 结果记录

这个结构的核心价值在于：

> **把 Prompt 改动从随意操作变成可追踪的实验过程。**

---

## 6. Prompt 优化通常在解决哪些类型的问题？

### 参考答案

当前阶段可以先分成四类：

1. 任务目标澄清
2. Tool 使用约束
3. 输出行为约束
4. 风险控制约束

这样分的价值在于：

- 知道自己到底在改哪类问题
- 避免一次改太多目标
- 让 Prompt 调整更聚焦

---

## 7. 为什么“补规则”不是唯一的 Prompt 优化方式？

### 参考答案

因为很多问题不一定是“规则太少”，还可能是：

- 角色定义不清
- 工具规则模糊
- 示例不足
- 信息冲突
- 约束过重

所以 Prompt 优化除了加规则，还可能包括：

- 重写目标描述
- 调整工具使用说明
- 增加示例
- 删除冲突规则
- 简化 Prompt

这说明 Prompt 优化不一定是加法，也可能是减法和重构。

---

## 8. 为什么 Prompt 越长不一定越好？

### 参考答案

因为 Prompt 过长会带来两个常见问题：

1. 重点被稀释
2. 规则之间更容易冲突

例如同时要求：

- 积极使用 Tool
- 尽量少调用 Tool

如果表达不清，模型就会摇摆。

所以 Prompt 的质量很多时候不取决于长度，而取决于：

> **是否清晰、一致、重点突出。**

---

## 9. 为什么固定评测集是 Prompt 迭代的护栏？

### 参考答案

因为如果没有固定样例集，你每次改 Prompt 都只能靠临时问几个问题。

这样的问题在于：

- 样例不一致
- 很难前后对比
- 很容易被偶然成功误导

有了固定评测集之后，你就可以比较 Prompt A 和 Prompt B 在同一组任务上的表现差异。

这会让 Prompt 迭代从主观判断变成可比较实验。

---

## 10. 第一版 Prompt 对照实验通常该怎么做？

### 参考答案

第一版可以非常简单：

1. 保留旧 Prompt 版本 A
2. 创建只改一个变量的版本 B
3. 用同一组固定样例分别跑 A 和 B
4. 比较任务成功率、Tool 正确率、平均轮数等指标
5. 判断是否保留 B

这已经构成一个最小可运行的 Prompt 实验闭环。

---

## 11. 为什么要保留 Prompt 版本历史？

### 参考答案

因为如果每次都直接覆盖原 Prompt，就会失去实验历史。

后续一旦效果变好或变差，你很难回答：

- 是哪次改动带来的
- 之前哪个版本更稳
- 是否值得回滚

所以 Prompt 也需要版本意识。

哪怕只是：

- `v1`
- `v2_tool_rule`
- `v3_finish_rule`

也比完全没有版本管理强很多。

---

## 12. 为什么有些问题不应该继续通过 Prompt 修补？

### 参考答案

因为并不是所有 Agent 问题都属于 Prompt 层。

如果问题本质上来自：

- Tool 结果质量差
- Memory 注入噪音高
- 上下文裁剪策略错误
- Runtime 流程有 bug

那么继续补 Prompt 很可能只是在掩盖系统问题，而不是解决根因。

所以在做 Prompt 优化前，需要先判断：

> **这真的是 Prompt 问题吗？**

---

## 13. 为什么 Prompt 优化本质上也需要评估体系？

### 参考答案

因为 Prompt 改动本身就是系统行为改动。

如果没有评估体系，你无法稳定判断：

- 任务成功率是否提升
- Tool 调用是否更合理
- 是否引入了新的副作用
- 平均轮数是否变多

所以 Prompt 优化必须依赖固定样例集和固定指标，否则就会退化成“感觉更好了”的主观操作。

---

## 14. 如果让你设计一个最小版 Prompt 实验流程，你会怎么做？

### 参考答案

我会这样做：

1. 先明确一个具体问题场景
2. 提出一个可验证假设
3. 只改 Prompt 的一个局部
4. 用固定样例集跑修改前后两个版本
5. 比较关键指标并记录结果
6. 决定保留、回滚或继续下一轮小改动

这个流程能保证 Prompt 迭代是可比较、可回滚、可解释的。

---

## 15. 面试时如何简洁总结这一课？

### 参考答案

可以这样回答：

> Prompt 迭代不能靠拍脑袋，而应该像实验一样进行。工程上要先明确问题现象和假设，再一次只改一个变量，用固定评测集对比改动前后的任务成功率、Tool 正确率和平均轮数等指标。这样才能避免 Prompt 越改越长、越改越乱，也能保住归因能力和回滚能力。
