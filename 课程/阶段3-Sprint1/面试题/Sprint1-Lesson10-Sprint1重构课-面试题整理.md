# Sprint 1 - Lesson 10 面试题整理

## 题目 1

**问题：** 为什么在 Sprint 里，“重构课”不是可有可无，而是必须存在的环节？

**参考答案：** 因为 Sprint 的目标不只是持续增加功能，还要周期性地把这些新增能力收敛成稳定结构。如果一个项目只做功能叠加、不做阶段性整理，就会迅速积累重复逻辑、命名混乱、职责漂移和技术债。重构课的作用正是阻止项目在学习和扩展过程中逐步腐化，让下一阶段仍然能在清晰边界上继续推进。

**追问方向：** 如果一个学习项目长期没有重构课，最常见的结构性问题是什么？

**易错点：** 把重构理解成“有空再做的优化”，而不是工程节奏的一部分。

## 题目 2

**问题：** 为什么说当前阶段的重构更准确地叫“收敛（Consolidation）”而不是“推翻重写”？

**参考答案：** 因为 Sprint 1 已经搭出了正确的基础能力，问题不在于方向错了，而在于前几节课的渐进实现可能留下了临时写法、命名不统一和边界松动等问题。此时最合理的动作不是推倒重来，而是把已经验证有效的能力整理、合并、统一、定型，形成更稳定的版本。因此这一阶段的重构本质是收敛已有成果，而不是重新发明。

**追问方向：** 哪些信号说明现在适合做“收敛”，而不是继续“扩功能”？

**易错点：** 一听到重构就以为前面都白做了。

## 题目 3

**问题：** Sprint 1 结束前，最应该优先收敛的技术债有哪些？

**参考答案：** 最值得优先收敛的通常包括：临时实现痕迹、重复逻辑、命名不一致、消息组织职责重叠，以及错误处理风格不统一。因为这些问题虽然短期不一定让系统立刻坏掉，但会显著提高下一阶段扩展成本。特别是在 Agent 项目中，一旦 Runner、Session、ToolManager 和 LLM 抽象都存在，这些边界上的混乱会很快放大。

**追问方向：** 为什么命名不统一在 Agent 项目里会比普通小脚本更痛？

**易错点：** 只盯着功能是否能跑，忽略结构和术语是否已经开始漂移。

## 题目 4

**问题：** 为什么 Sprint 1 重构课之后，不应该继续立刻往单 Agent 里堆新功能？

**参考答案：** 因为 Sprint 1 的真正价值是把“最小 Agent Framework”打稳，而不是让单 Agent 一直横向长功能。如果在没有收敛基础结构的前提下继续往里加 Logging、Memory、MCP、RAG 等能力，只会让技术债和边界问题不断累积。正确做法是先确认基础层稳定，再进入工程化阶段，这样后面的功能增长才建立在可靠地基上。

**追问方向：** 什么情况下可以判断“现在可以结束 Sprint 1，进入下一阶段了”？

**易错点：** 误把“更多功能”当作“更多进步”。

## 题目 5

**问题：** 为什么说 Sprint 的价值不只是做出功能，而是周期性把功能收敛成结构？

**参考答案：** 因为功能本身只回答“系统现在能做什么”，而结构回答的是“系统未来还能不能继续长”。如果没有结构收敛，功能会以技术债的形式堆积，最终变成一个越来越难改、难测、难扩展的系统。Sprint 的真正价值，是在每轮能力新增之后，通过重构和整理把这些能力变成下一轮可以继续承载更多东西的稳定基础。

**追问方向：** 这个原则放到 Agent Framework 开发里，为什么比普通 CRUD 项目更关键？

**易错点：** 只把 Sprint 理解成时间切片，而不是演进结构的节奏单元。

## 题目 6

**问题：** 为什么说一个学习项目最后失败，往往不是功能做不出来，而是“没有收敛机制”？

**参考答案：** 因为学习项目早期通常都能堆出不少功能，但如果没有收敛机制，项目会越来越像一系列 lesson 拼接物：文件越来越多、命名越来越散、边界越来越模糊、测试越来越跟不上。到了某个阶段，开发者会开始不敢改代码，最终项目虽然“东西很多”，却无法继续健康演进。所以失败点通常不是能力不足，而是没有把阶段成果周期性整理成稳定结构。

**追问方向：** 如果让你给一个正在变乱的 Agent 学习项目做一次收敛，你会先看哪三类问题？

**易错点：** 觉得重构课只是文档总结，而不是项目生死线的一部分。
