# 课程架构与维护规则

## 唯一主线

课程只有 M01-M08 八个主线里程碑。每个目录固定包含：

- `课程.md`：目标、设计、代码入口、任务和验证命令。
- `验收与面试.md`：产物检查、代码讲解、故障分析和设计取舍。

不再维护“一课一份面试题”，不再用课程数量衡量进度。

## 新增内容的门槛

只有满足以下任一条件才可新增内容：

1. 主项目出现新且可复现的工程问题。
2. 官方 API 发生影响现有代码的变化。
3. 固定评测发现稳定失败类别。
4. 作品交付需要新的可验证能力。

优先更新已有里程碑。只有跨越多个里程碑且具备独立产物时，才增加选修专题；不得增加 M09 作为默认动作。

## 文档完成标准

- 指向真实存在的源码和测试。
- 至少给出一个自动验证命令。
- 区分已实现、实验中和仅设计三种状态。
- API 相关内容记录最后核验日期和官方来源。
- 模型名、价格、SDK 版本等易变信息不得描述为永久事实。
- 不把 Prompt 约束写成安全保证。

## 项目完成标准

任何里程碑必须同时具备代码、测试、运行记录和答辩材料。文档先于实现时必须明确标记“未实现”，不能把界面草图或伪代码列为已交付能力。

## 归档规则

`归档/2026-07-深度重构前/` 保存原 56 节课程、56 份面试题和旧治理文档。归档只读；需要修正历史错误时，在新主线中记录更正，不原地维护两套内容。

## API 核验规则

课程实现 OpenAI Function Calling 时，以 Responses API 的 `response.output`、`function_call` 和 `function_call_output` 机制为基准。结构化模型输出与 Runtime 的 `RunResult` 分层。OpenAI Agents SDK 仅作为架构对照，不成为主项目运行依赖。

- 最后核验日期：2026-07-13
- [Function calling](https://developers.openai.com/api/docs/guides/function-calling)
- [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)
- [Agents SDK](https://developers.openai.com/api/docs/guides/agents)

## 自动检查

课程结构由 `agent-from-scratch/tests/test_course_structure.py` 验证。提交前至少执行：

```powershell
cd agent-from-scratch
python -m pytest -q
```
