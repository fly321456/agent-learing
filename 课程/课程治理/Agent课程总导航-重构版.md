# Agent课程总导航（重构版）

## 这份导航解决什么问题

这份导航只解决一件事：

> 你现在应该按什么顺序学习，才能真正成长为一名 Agent 开发工程师。

从现在开始，这个仓库**默认不再继续线性扩写新课程**。
原因不是内容不够，而是课程基础已经足够完整，继续无上限加课，收益会越来越低，反而会削弱真正重要的事情：

1. 把已有内容学透。
2. 把知识落实到主项目。
3. 把主项目持续迭代成作品级仓库。

所以，后续学习主线不再是“继续听下一课”，而是下面三条并行主线：

1. 课程复习主线
2. 主项目开发主线
3. 仓库作品化主线

---

## 唯一推荐学习顺序

### 第一阶段：阶段1-核心认知

学习路径：

1. `课程/阶段1-核心认知/第一课-什么是Agent-学习整理.md`
2. `课程/阶段1-核心认知/第二课-Tool Calling本质-学习整理.md`
3. `课程/阶段1-核心认知/第三课-Agent项目结构-学习整理.md`
4. `课程/阶段1-核心认知/第四课-Tool Schema与三层世界-学习整理.md`
5. `课程/阶段1-核心认知/第五课-第一个Agent Loop认知-学习整理.md`
6. `课程/阶段1-核心认知/第六课-Responses API与事件输出-学习整理.md`
7. `课程/阶段1-核心认知/第七课-状态机与事件流-学习整理.md`

这一阶段的目标不是记笔记数量，而是吃透七个最核心概念：

- Agent = LLM + Tool + Loop
- Tool Calling 的本质是结构化决策，不是模型执行代码
- Tool Schema 是给模型看的接口说明书
- 用户世界、LLM 世界、Python 世界必须分清
- Agent Loop 是 Agent 的灵魂
- Responses API 返回的是事件，不只是文本
- Agent 本质上是状态机 + 事件流

学习要求：

- 学完每一课，口头复述一次。
- 每学完两课，去看对应面试题整理。
- 如果一个概念说不清，就不要急着进入后面阶段。

---

### 第二阶段：阶段2-项目过渡

学习路径：

按文件顺序快速过一遍即可。

这一阶段的作用不是新增大量知识，而是完成思维切换：

- 从“概念理解”切到“工程实现”
- 从“Agent 是什么”切到“Agent 应该怎么拆模块”
- 从“课程视角”切到“项目视角”

学习要求：

- 这一阶段不必反复精读。
- 抓住重点：`Agent`、`Runner`、`LLM Interface`、`Tool Manager` 这些职责边界。
- 如果你已经能清楚解释这些边界，可以直接进入 Sprint 1。

---

### 第三阶段：阶段3-Sprint1

学习路径：

从 `课程/阶段3-Sprint1/` 的第一课开始，按顺序学习。

这一阶段是整个课程第一次真正进入“开发主线”。

目标不是继续增加理论，而是完成下面这件事：

> 自己实现一个最小可运行 Agent，并真正理解它为什么能工作。

这一阶段重点关注：

- Agent 为什么只是配置
- Runner 为什么负责运行
- BaseLLM / OpenAILLM 为什么要分层
- Tool 执行链路怎么闭环
- 最小 Agent Loop 怎样落地

学习要求：

- 每一课都要回到 `agent-from-scratch/` 或你的主项目里落代码。
- 不要只看文档不实现。
- 这一阶段结束时，你至少要有一个能跑通单 Agent + Tool Calling 的版本。

---

### 第四阶段：阶段4-工程化能力

这一阶段已经很丰富，不需要再继续无止境扩课。

正确学法不是从 Lesson1 一直机械读到 Lesson31，而是按模块学习。

#### 模块A：单 Agent 工程化基础

建议顺序：

1. Logging
2. Tracing
3. Retry 与 Timeout
4. Config 管理
5. Token 与上下文窗口管理
6. 上下文压缩与摘要策略
7. Memory 分层设计
8. Memory 写入与检索注入
9. Tracing 事件模型深化
10. 调试方法论与故障定位
11. 评估指标与最小评测体系
12. Prompt 迭代与实验设计
13. Tool 设计质量与接口重构
14. Session 状态治理
15. 检查点与可恢复运行
16. 长任务调度与人工接管点

这一模块的目标：

> 把“能跑的 Agent”升级成“可维护、可调试、可恢复、可评估的 Agent”。

---

#### 模块B：RAG 能力接入

建议顺序：

1. 最小 RAG 接入
2. 检索质量、切分与注入优化
3. RAG / Memory / Session 三层协同

这一模块的目标：

> 让 Agent 学会正确使用外部知识，而不是把所有信息都硬塞进上下文。

---

#### 模块C：MCP 前置认知

建议顺序：

1. Tool 系统标准化
2. MCP 到底标准化了什么
3. MCP、OpenAI Agents SDK、Claude Code 的共同抽象

这一模块的目标：

> 理解 MCP 不是“又一个框架”，而是 Tool 生态标准化。

---

#### 模块D：多 Agent 前置能力

建议顺序：

1. 角色分工抽象
2. Planner / Executor / Reviewer 经典三角
3. 多 Agent 的成本意识
4. 从多 Agent 回看单 Agent
5. 可拆分性审计
6. 第一版协作协议设计
7. 共享状态、局部状态与状态主权
8. 多 Agent 的评估、归因与失败定位

这一模块的目标：

> 在真正上多 Agent 之前，先建立拆分意识、协作意识和治理意识。

---

#### 模块E：回到项目

最后学习：

- `课程/阶段4-工程化能力/Lesson31-从课程回到项目——如何把你现在的Agent训练营真正落成一个可持续迭代仓库-学习整理.md`

这一课不是补充课，而是整个阶段4的落点。

它解决的是：

> 学了这么多，最后如何真正沉淀成一个长期维护的 Agent 项目。

---

## 现在开始，不再默认继续生成新课

默认策略调整如下：

1. 不再把“继续生成下一课”作为主动作业方式。
2. 优先做已有课程的学习、归纳、回顾和落地实现。
3. 优先把知识转成主项目代码、测试、日志、Tracing、文档。
4. 后续若新增课程，只能围绕主项目遇到的真实问题增量补课。

也就是说：

> 以后课程是为项目服务，不再反过来让项目为课程服务。

## 你现在到底应该怎么学

如果你今天重新开始，直接按下面方式执行：

### 第1周

- 完成阶段1全部学习整理 + 面试题整理
- 目标：能清楚讲明白 Agent / Tool / Loop / Responses / 状态机

### 第2周

- 快速过阶段2
- 完成阶段3-Sprint1 前半部分
- 在主项目里跑通最小 Agent

### 第3周

- 完成阶段3-Sprint1 后半部分
- 把单 Agent + Tool Calling + Runner 跑起来

### 第4周到第6周

- 进入阶段4 模块A
- 重点建设：Logging、Tracing、Retry、Config、Memory、Session

### 第7周到第8周

- 进入模块B 和模块C
- 给主项目加最小 RAG 和 MCP 认知基础

### 第9周以后

- 进入模块D
- 先做可拆分性审计，再决定是否真的引入多 Agent

## 课程之外，真正的主线是什么

从现在开始，你的真正主线只有一句话：

> 一边复习课程，一边把 `agent-from-scratch/` 或后续主项目持续迭代成一个作品级 Agent 仓库。

所以请把精力优先放在：

1. 主项目代码
2. 主项目文档
3. 主项目测试
4. 主项目运行记录
5. 主项目迭代日志

而不是继续追求“我又多学了几课”。
