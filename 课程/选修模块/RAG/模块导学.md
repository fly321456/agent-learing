# RAG 选修导学：让 Agent 使用外部知识，但不混淆状态与事实

本选修建立在 32 节主线之后，不修改核心 Runtime，也不引入向量数据库。目标是先看懂 RAG 的最小数据流和失败边界，再决定是否需要 Embedding、向量库或重排序器。

```text
R01 无 RAG 基线：没有证据就明确不知道
  → R02 Chunk / Index / Top-K：确定性最小检索
  → R03 RAG Tool：来源保留与提示注入隔离
  → R04 Recall@K：检索评测与 RAG/Session/Memory 边界
```

实验完全离线：

```powershell
cd agent-from-scratch/course-labs/rag
python steps/r01_no_rag_baseline.py
python steps/r02_chunk_and_retrieve.py
python steps/r03_sources_and_injection.py
python steps/r04_retrieval_eval.py
python demo.py
```

完成后，你应能解释为什么“检索到了”不等于“回答正确”，能把恶意文档标为不可信证据，能计算 Recall@K，并能判断一个需求应使用 RAG、Session、Memory 还是 Coding Tool。
