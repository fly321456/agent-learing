# RAG 模块验收与面试

## 自动验收

```powershell
cd agent-from-scratch
python -m pytest -q tests/test_course_rag.py
python -m compileall -q course-labs/rag
python course-labs/rag/demo.py
```

## 功能检查

- 无检索基线不会编造私有事实。
- Chunk 保留 source，overlap 参数受校验。
- 倒排检索 Top-K 与同分排序确定。
- 恶意文档原文保留但标为 untrusted evidence。
- 格式化 Context 明确禁止执行来源内指令。
- Recall@1/2 根据实际 rankings 计算，不静态打印。
- RAG 实验不依赖最终 Runtime、网络或向量数据库。

## 故障注入

1. overlap 等于 chunk_size。
2. Query 无匹配却强行回答。
3. 恶意文档伪造 SYSTEM MESSAGE。
4. Top-K 返回全部文档。
5. 正确来源命中但被 Context Builder 丢弃。
6. 把 Session 摘要写入长期 RAG 并当作事实。

## 精选面试题

1. RAG 的 Grounding 是什么？
2. 为什么先建立 No-RAG Baseline？
3. Chunk 太大或太小分别有什么问题？
4. Recall@K、Precision@K、MRR 分别衡量什么？
5. 间接提示注入如何进入 Agent？
6. 来源引用为何不能完全保证真实性？
7. RAG、Session、Memory 的边界是什么？
8. 什么时候关键词检索优于向量检索？

## 通过标准

能运行全部离线实验；能手算一个 Recall@K；能解释一个检索失败和一个生成失败；能展示恶意来源不会绕过 Tool 审批。只会调用向量数据库 API、不理解证据与安全边界，不算通过。
