# R02 切分、索引与最小检索：先看懂 Top-K，再引入向量模型

> 建议学习时间：60–90 分钟。本课使用确定性倒排索引，不增加向量数据库或 Embedding 依赖。

## 1. 本节要解决的真实问题

把整份 200 页手册直接放进模型 Context 成本高、噪声大，也可能超限。RAG 需要先把 Document 切成 Chunk（文档片段），为片段建立 Index（索引），再按 Query 返回最相关 Top-K。

但切分不是机械字符操作：片段过大带入无关内容，过小会把“Acme server uses port 4312”拆成两段；没有 overlap 可能丢失边界语义，overlap 太大又制造重复。索引若不保留 source，模型即使答对也无法引用。

问题链是：Document 与 Chunk 有何区别？Chunk ID 如何稳定？overlap 为什么必须小于 chunk_size？倒排索引怎样评分？同分结果如何保持确定？Top-K 越大越好吗？

## 2. 数据流与核心对象

```text
Documents
  → chunk_document(size, overlap)
  → Chunks(id, source, text)
  → InvertedIndex
  → search(query, top_k)
  → SearchResults(chunk, score)
```

Document 保存来源和原文；Chunk 保存稳定 id、来源和局部文本；SearchResult 将片段与分数组合。不要只返回字符串，否则后续无法评测来源排名。

教学代码位于 `agent-from-scratch/course-labs/rag/rag_lab.py`。

## 3. 类比与两个切分案例

切分像给一本书制作索引卡。每张卡应包含足够完整的观点，又不能抄整章。

案例一：文本 `abcdefghij`，chunk_size=6、overlap=2，得到 `abcdef` 与 `efghij`。`ef` 重叠，跨边界信息仍出现在后一片段。案例二：chunk_size=6、overlap=6，step 变成 0，循环无法前进，所以必须拒绝。

自然语言项目通常优先按标题、段落或代码符号切分，再用字符上限兜底；本课字符切分用于把算法讲清并保持离线确定。

## 4. Document 与 Chunk 设计

```python
@dataclass(frozen=True)
class Document:
    source: str
    text: str

@dataclass(frozen=True)
class Chunk:
    id: str
    source: str
    text: str
```

Chunk id 由 `source#index` 构成，便于测试和引用。同一文档内容变化后 index 可能指向不同文本，生产系统更适合加内容哈希和索引版本。

source 使用可展示的相对标识，不泄露本机绝对路径。

## 5. 本课唯一代码增量：重叠切分

```python
step = chunk_size - overlap
for index, start in enumerate(range(0, len(document.text), step)):
    text = document.text[start:start + chunk_size]
    chunks.append(Chunk(f"{document.source}#{index}", document.source, text))
    if start + chunk_size >= len(document.text):
        break
```

空文档返回空列表；chunk_size 必须正数；`0 <= overlap < chunk_size`。最后一个片段可以短于上限，但不能添加空 Chunk。

显式 break 避免已经覆盖文档末尾后继续产生纯重叠尾片段。

## 6. 最小倒排索引

倒排索引思想是“词 → 出现在哪些片段”。教学版为每个 Chunk 保存小写 token set，Query 也转 token set，以交集数量作为分数。

```python
score = len(query_tokens & chunk_tokens)
```

Query `Acme port` 与 `Acme server uses port 4312` 交集为 2；与 `Acme client configuration` 交集为 1，因此前者排名更高。零分结果不返回。

这不是先进检索器，却透明、可解释、适合验证 Top-K 管线。

## 7. 两个错误直觉与纠正

### 误区一：必须先上 Embedding 才叫 RAG

RAG 的核心是检索证据再生成。关键词索引同样是检索，且对端口、类名和配置键可能更准确。先有基线，再用评测证明向量检索值得。

### 误区二：Top-K 越大召回越好，答案也越好

K 增大可能提高 Recall，却增加噪声、重复和 Context 成本。生成质量取决于相关证据是否靠前，而不是片段总数。

另一个误区是按文件遍历顺序处理同分。文件系统顺序可能跨平台变化；教学实现以 `(-score, chunk.id)` 排序，确保回归稳定。

## 8. 完整检索轨迹

```text
Chunks:
  a#0 source=a.md tokens={acme,server,uses,port,4312}
  b#0 source=b.md tokens={acme,client,configuration}
  c#0 source=c.md tokens={unrelated,notes}
Query tokens={acme,port}
Scores: a=2, b=1, c=0
top_k=2 → [a.md, b.md]
```

SearchResult 保留 score，后续可以设最低阈值或分析边缘结果。

## 9. 检索器的工程边界

索引构建与查询应分离。文档更新后需要重建或增量更新；Query 不应每次重新 tokenize 全部文档。教学数据很小，类中缓存 Chunk token。

```python
self._tokens = {chunk.id: _tokens(chunk.text) for chunk in chunks}
```

中文分词不能靠 `[a-z0-9_]`，真实中文知识库需选择分词或字符 n-gram；不要误把英文教学 tokenizer 宣称为通用实现。

索引还必须记录 chunk_size、overlap、tokenizer 和构建时间，才能复现实验。
